# 独立链上 DAO 仲裁

更新日期：2026-09-12。案件、Escrow、奖励池、Chainlink VRF v2.5 subscription 与 8 名创始仲裁员已在 Sepolia 启用；真实奖励付款已经确认。新版案件已分别完成中位数结算、参与不足恢复退款，以及钱包付费申诉、终审结算和保证金取回闭环。真实文件附件的上传、鉴权下载、摘要复核、钱包锚定与刷新恢复也已完成公共测试网验收。

## 用户流程与资金边界

1. 当事人发起争议，平台冻结任务；独立案件登记交易确认后开始举证窗口。
2. 证据正文保留在权限数据库。当事人可用钱包将文字及附件引用的内容承诺上链，正文不公开。
3. 举证截止后，平台提交合格候选快照，合约现场检查 YD 资格并排除利益相关钱包。
4. Chainlink VRF v2.5 返回随机数，任何人均可按固定规则推进抽签。首审 3 人，2 票同类形成多数；全员投票或截止后计票。
5. 首审结论进入申诉期，任务 USDC 不释放。任一当事人可以申请一次独立 5 人终审，排除首审成员。
6. 无人申诉且窗口到期，或终审至少 3 人参与后按全部有效比例的中位数计票，形成最终裁决。
7. 平台读取已确认的链上裁决，复用现有多 Agent 分账与资金 outbox；最终结算交易确认后才解除冻结。

首审无多数会免费升级终审。新版合约中，终审参与不足会进入有硬截止的 `recovery`：恢复角色可在窗口内依据完整卷宗给出带理由承诺的裁决，窗口到期后任何人都能执行部署时公开的兜底比例。全案另有硬期限，候选不足、VRF 长期不返回等任一阶段超时后都可进入同一恢复流程，任务资金不会永久冻结。

旧版 Sepolia 合约不可升级且仍使用历史 `stalled` 规则；其中已冻结的旧案不能因本地代码改变而自动恢复。新版 Escrow 与案件合约已经另行部署并启用上述恢复逻辑，新任务使用新版地址，旧任务和旧资金不迁移。

独立 `ArbitrationRewards` 持有奖励 YD；`ArbitrationCases` 只持有申诉保证金/服务费；
`ArbitrationDAO` 继续持有成员质押；`Escrow` 只持有任务预算。四者不借用对方资金。
USDC 仲裁服务费不会自动变成 YD 奖励，奖励池需要平台独立补充 YD。

## YD 与费用

- 不提供无条件公共申领入口。创世期额度为：新用户完成验证 5 YD、真实资金托管的需求 5 YD、
  需求成功完成后发布者 15 YD、Agent 验证通过 10 YD、Agent 首次成功交付额外 15 YD、
  Agent 每次成功交付 20 YD、有效仲裁投票 10 YD。首次交付同时满足“首次”和“每次”两项；
  空需求和未经验证的 Agent 上架不直接发奖，单钱包活动上限为 100 YD。
- `ArbitrationRewards.award` 由授权分配者提供唯一业务凭证及任务/活动来源分类，合约防重复；业务凭证的真实性由平台审核边界负责，合约不会读取数据库来证明活动完成。
- 默认自动发放：计票或授权发奖先记入固定受益人的待发账，后台调用 `payReward(sourceId, recipient)` 并承担 Gas。不铸币、不修改原有 YD 质押，不需要用户签名领取。
- 支付金额由合约已记录的凭证决定，调用者不能改金额或重定向收款；重复推进不会重复付款。单笔代币转账失败只回滚该奖励，不回滚仲裁计票。
- 每轮开案/升级前先从平台奖励池预留全组奖励。有效投票者获得相同参与奖励，不以“必须跟多数一致”作为奖励条件；未投票部分退回可用池。
- 申诉保证金与服务费分别记录，页面显示合计授权额；默认部署不配置金额、不启用收费。
- 保证金规则支持“始终退还”和“改判退还、维持则转独立仲裁金库”，必须经产品确认后显式选择。服务费不退。终审参与不足进入恢复期时不视为申诉败诉，保证金记为可退还。
- 启动期最低质押门槛已于 2026-09-06 经用户确认调整为 100 YD。上述创世奖励额度和单钱包上限已经确认；Sepolia 新案的申诉保证金为 1 USDC、服务费为 0.1 USDC，保证金采用 `ReturnAlways`。正式生产窗口仍须结合仲裁员响应目标另行确定。

启动期门槛为 100 YD，本地现有合约与部署清单已同步，新建本地 DAO 默认使用同一门槛。
创世奖励使用独立可重放 worker 从权威业务事实补扫；业务事实、奖励命令、链上分配和付款
分阶段恢复，任一奖励故障都不能回滚登录验证、任务结算、Agent 准入或仲裁投票。
质押不是入会费：当前本地部署申请退出后等待 7 天，可取回全部质押。
降低门槛不自动退回已有质押；调整时须同步合约、部署清单与 API 配置，不能只改页面。
已有其他网络的部署也不会因修改本地默认值而自动变更，需其配置管理员单独确认交易。

任务/活动资格核对和历史补发已由创世奖励 worker 实现；迁移、奖励池授权与充值完成前仍不能描述为当前环境已经发放。仲裁奖励按有效投票记账，与是否跟多数意见一致无关。

### 自动到账与通知（2026-09-06）

- `dao_reward_transfers` 从确认的 `RewardAllocated` 事件建账，`dao_reward_attempts` 先保存签名再广播；响应丢失只重播原交易，失败回执按 60 秒退避重试，最多 5 笔链上失败后等待平台处理。签名前的 RPC/模拟故障不消耗 Gas，每分钟重新检查。
- `RewardPaid` 的确认事件才将记录变成 `paid`，同时成为该钱包的未读站内通知；普通成功回执、广播返回哈希或乐观页面状态都不触发到账提醒。
- Header 的奖励入口始终显示，存在未读奖励时才显示数字角标；在线新到账弹一次提示，首次打开只呈现历史未读数。工作台入口、Header 与奖励页统一使用奖励图标。DAO 奖励记录每页 10 条，显示来源、金额、待发/确认/到账状态和交易入口；用户进入奖励页后，当前页自动标记已读并同步 Header 未读数，失败时保留未读并在后续轮询自动重试。不发送邮件或浏览器系统推送。
- 在线提示读取同链、奖励池和钱包的累计确认到账额增量，不依赖当前列表第一页；延迟到账的旧奖励或超过 10 笔的批次也能提示合计金额。切换范围/首次启用只建立基线，读取失败保留原基线，未读数与跨设备已读仍独立维护。
- 已同步区块发生重组会暂停该奖励池的自动支付并拒绝展示可能错误的到账记录；只有旧游标范围内全部奖励与付款语义在当前确认链一一重现，受控运营入口才解除冻结。真实历史分叉继续等待人工治理，不自动重抽、默认退款或覆盖旧交易。
- 手动领取钱包流程与其测试已删除，奖励页面不再提供领取按钮；申诉 USDC 的保证金退款入口是另一种业务，不受此次 YD 自动发放变更影响。
- 当前不可升级案件合约将可退申诉保证金记入当事人的 `usdcCredit`，由当事人在争议详情主动领取。页面明确区分保证金和不退的服务费；首次检测到余额时给文字提示，不增加只能跳到争议列表的独立头部图标。
- `0042` 于 2026-09-06 在隔离测试库及体验库执行，当时体验库为 v42；当前版本见“Sepolia 当前状态”。本地两笔各 1 TestYD 的开发钱包验收不属于产品奖励费率，也不是用户完成任务就自动获奖的业务规则。
- `DAO_REWARD_CASE_ADDRESS` 仅启用奖励目录，不开启新版案件或改变旧任务仲裁。后续配置 `ARBITRATION_CASES_CONTRACT_ADDRESS` 时，两者必须一致，禁止查询池与案件池错配。

`POST /api/dao/cases/:disputeId/actions` 仅准备白名单钱包交易，或确认已上链证据；不会替用户签名。
`POST /api/internal/workers/dao-cases` 使用独立内部 Bearer token，推进已有案件。
`POST /api/internal/workers/dao-cases/retry` 只恢复未签名失败命令；对账冻结或阶段已变化时明确拒绝。
`POST /api/internal/workers/dao-cases/reconcile` 处理已签名回滚与最终裁决重组：未知或已确认成功的旧回执不会生成第二笔交易；回滚交易的原始字节、哈希和 nonce 永久保留在 0043 尝试表，最多五次。存在第二次尝试或当前命令指针已与历史分离时，0043 down migration 会拒绝丢弃恢复历史。重组解冻要求当前确认链除区块位置外的完整案件语义与原 Final 一致，并只恢复因该冻结进入死信的仲裁 outbox。
`POST /api/internal/workers/dao-rewards/reconcile` 接受旧 `nextBlock`、旧边界区块哈希和固定恢复原因。服务端按配置的链、奖励池和起始块重放到旧边界，并在所有分配及付款的来源、收款人、类型、金额和付款交易一致后，更新新区块位置、解除游标冻结并写共享审计。扫描期间再次重组、缺少事件或出现替代付款时事务不落库，自动发奖与奖励展示继续冻结。
证据交易状态也通过同一案件 actions 入口核验：无回执、确认不足或孤块保持 pending；只有规范区块中的回滚回执，且原交易 calldata 的案件、证据和内容承诺均匹配，才向该钱包开放再次主动签名。同一证据的全部本地已知哈希都必须完成核验，页面不会自动广播。
当前尚无运营页面；案件恢复调用方必须使用内部 Bearer Token，并提交旧错误码/交易哈希、告警 ID 或奖励游标乐观锁及枚举恢复原因。仓储在事务内重新锁定权威状态，避免依据过期页面误清错误。
旧版投票入口仍是 `POST /api/dao/cases/:roundId/votes`，不能把两个 ID 或裁决语义混用。

## VRF 的保证与限制

- 请求 ABI 对齐官方 Chainlink contracts 1.5.0 的 VRF v2.5 `RandomWordsRequest`；合约仅接受固定 coordinator 回调，不自行验证或伪造 VRF 证明。
- 回调只存随机数，组建小组另行调用，避免遍历、转账或数据库故障让不可重试的 VRF 回调失败。
- 请求发出后不能换候选、取消或重新抽签；链下未广播的失败不算已请求。
- 候选必须有序唯一，最多 256 人，且首审至少 3 人、终审至少 5 名未参与首审者。当前尚未实现更大候选池的链上分片抽样。
- 候选集合仍由授权平台注册者提供，VRF 只保证从已承诺集合中随机选择，不能证明平台没有遗漏其他成员。
- 成员申请退出后不会进入新候选快照；已选入案件的投票权保留，不实现未投票罚没或延长质押锁期。
- VRF 未返回时不能用服务器随机数代替；新版合约到达全案硬期限后允许任何人转入恢复期，并在恢复硬截止后执行公开兜底。

### 启动期创始成员与社区交接（更新至 2026-09-10）

- 创始成员只是公开的部署级候选名单，不拥有逐案指定、直接裁决或绕过 VRF 的权限；每个钱包仍须真实质押 100 YD、未申请退出，并通过任务参与方和首审成员排除。
- 创始名单必须包含 8～64 个不重复钱包。少于 8 名已同步社区成员时，新案固化为 `bootstrap` 并允许全部合格创始成员与社区成员进入候选；8～11 名时固化为 `mixed`，最多保留地址确定排序的 5 名创始成员；达到 12 名时固化为 `community`，新案只使用社区成员。
- 阶段、开案时社区人数和完整创始名单写入 0044 的 `candidate_pool_policy`。环境变量、成员人数或运营策略后续变化不能改写既有案件；每轮真正请求分案前仍在同一确认区块复核链上资格，然后把冻结候选交给 Chainlink VRF。
- 未配置 `DAO_FOUNDING_ARBITRATOR_ADDRESSES` 的旧部署保持原社区候选行为。DAO 页面通过匿名只读接口公开当前同步投影中的阶段、创始/社区数量和 12 人交接门槛；接口不返回成员地址、个人资格或案件。该展示不是链上实时资格，worker 的确认区块复核仍是分案依据。
- 0044/0045 已应用到当前体验库，体验库后续迁移已推进至 v57、`dirty=false`；DAO 最后一次结构变更仍为 0050。8 个项目专用 Sepolia 创始钱包已分别质押 100 YD 并同步入库；页面已用真实聚合数据展示配置数量和当前可用数量，多起真实案件也已完成确认区块资格复核与 VRF 抽取。

## 证据保护

正文提交时生成域分离承诺，包含案件 ID、证据 ID、提交者、原始正文和稳定排序的附件引用。
数据库触发器拒绝改写/删除已承诺正文；读卷宗和生成资金计划前会复算，异常时拒绝结算。
当事人的链上交易另外锚定内容哈希，服务端检查成功回执、事件、提交者、目标合约和确认区块。

新上传文件由 `0048` 直接保存原始字节并计算 SHA-256，引用同时包含对象 ID 与摘要。提交证据时服务端重新核对案件、上传者、元数据、摘要和正文；提交后数据库触发器禁止修改或删除，授权下载时再次复算摘要。该实现不依赖 AWS，也不把远端 URL 当作已保护字节。
数据库超级管理员仍可能绕过数据库约束；链上承诺使已锚定内容被替换可被识别，但不能证明内容真实。当前单库保存也不等于异地备份，正式环境仍需数据库备份、恢复演练和访问审计。
仅准备交易或仅写入数据库，不显示成“已完成链上锚定”。

钱包广播证据交易后，浏览器按钱包、链、案件合约和案件隔离保存每条证据的 ID 与交易哈希。
刷新后仅为当前钱包所属且卷宗完整性正常的未锚定证据提供手动同步入口；本地记录属于不可信恢复线索，
不能代替服务端回执/事件核验，也不会触发自动签名或广播。每条证据的不同交易尝试分别存储，避免标签页互相覆盖已广播哈希。
存储不可用时当前页面仍保留哈希并支持复制，但无法保证刷新后恢复；已回滚交易的重新签名仍需另行处理。
切换钱包后又切回、且旧请求此时才返回哈希时，记录仍写入原钱包范围，但当前页面需刷新才能读取。

## 失败与回滚

- 已签名交易先保存再广播，响应丢失或重启只重发原始交易。
- 确认快照读取失败时本轮停止命令签名/广播；Final 回到 None 也触发重组保护，未解决的对账冻结持续阻止推进。候选上限等单案失败可以确认此前的交易回执；只有未知 nonce 继续阻塞，避免把已确认的开案交易永久留在 submitted。
- 确认回滚/预执行失败进入显式失败，不无限消耗 Gas。未签名命令只在错误码、阶段和冻结状态复核后重试；已签名命令先核对回执，只有确认回滚才清除当前指针并重新排队，旧原始交易与哈希仍保留在不可变尝试历史中。
- 用户证据交易的回滚不由后台重发。页面保留每个已广播哈希；服务端同时核对规范回执和原始 calldata，全部已知尝试确认回滚且举证期仍开放时才允许用户重新签名。
- 未应用迁移时旧功能继续使用原表，新链上案件拒绝降级；应用不会自动执行数据库 DDL。
- `0041` 保留资金与审计记录，不提供删除这些记录的 down migration；回滚应用时禁用新案入口，保留新表用于恢复。
- 当前 Sepolia 运行配置已启用新案件、托管和奖励 worker；老任务与本地历史链仍保留，未重置或搬迁。服务停止期间不会推进命令，重启后从数据库中的持久化签名与游标恢复。
