# 安全规则

项目技术栈已经冻结。以下领域约束适用于所有模块；Hono Business API 的外部输入使用 Zod 在边界校验，PostgreSQL 查询必须参数化。提供者钱包认证方案已冻结为 SIWE（EIP-4361，见 `specs/PLAN.md`），任何客户端可控 Header、请求体钱包地址或查询参数都不得冒充已认证主体，一律以 `resolveActorId` 解析出的 session 为准。

## 认证与授权

1. 所有跨系统边界的请求（任务发布者、Agent、Ops 后台）必须先认证再授权；不得仅凭请求体中的 ID 字段判定身份。
2. 权限判断在服务端统一执行，不得信任客户端/Agent 上报的角色或权限字段。
3. Agent 侧签名、Token、密钥等凭证必须校验有效期和签发方，过期或来源不符必须拒绝，不得静默放行。
4. 涉及资金、托管状态、争议裁决的操作，必须校验操作者与资源归属关系（如仅任务发布者可发起争议、仅托管账户绑定 Agent 可发起提现）。

## 钱包与资金操作（对应 feature 5/6/16）

5. 金额、余额计算禁止使用浮点类型；须使用定点/整数最小单位表示，避免精度丢失。
6. 钱包地址变更（feature 16）等敏感操作必须满足已确认的多重防护（签名验证 + 冷却期 + 站外通知），不得因实现方便跳过任一环节。
7. 资金状态迁移（托管创建、锁定、释放、退款）必须幂等：重复回调/重试不得导致重复扣款或重复放款。
8. 与链上/第三方支付的同步逻辑必须处理超时、失败和不一致状态，须有对账或补偿路径，不得假设外部调用总是成功。

## 外部 Agent 与回调输入

9. 来自外部 Agent 的执行结果、健康上报、匹配响应等一律视为不可信输入，必须做结构与取值范围校验后才能进入业务流程。
10. Agent 沙箱准入（feature 15）判断逻辑集中在单一权威位置，不得在多个入口重复实现或出现不一致判据。
11. Webhook / 回调类接口必须校验来源签名或密钥，防止伪造回调触发资金或状态变更。

## 密钥与敏感信息

12. 密钥、Token、私钥等敏感凭证不得硬编码、不得提交到仓库，不得出现在日志中。
13. 日志与错误信息中不得包含完整钱包地址、密钥、认证 Token 等敏感字段；必要时脱敏展示。

## 输入校验与常见漏洞

14. 所有外部输入（HTTP 请求体、查询参数、Agent 上报数据）在边界处做类型与业务规则校验，禁止直接拼接到查询语句或命令中。
15. 涉及数据库查询一律使用参数化/预编译方式，禁止字符串拼接 SQL。
16. 面向用户展示的内容（任务描述、Agent 资料等）在渲染前做转义或使用安全的模板机制，防止存储型 XSS。

## dispatch-engine（Go）专属规则

19. `services/dispatch-engine` 的 Agent 签名认证（feature 1）必须使用常量时间比较（如 `crypto/subtle.ConstantTimeCompare` 或等价方式）校验签名，禁止使用 `==` 或普通字符串比较，防止时序攻击。
20. 幂等键（idempotency key）校验与状态存储必须在 `internal/protocol` 单一权威位置实现，禁止在多个 handler 中各自实现幂等判断逻辑。
21. 沙箱标记（sandbox flag）等准入判据的写入仅允许服务端内部逻辑触发，不得信任请求体中携带的沙箱状态字段。
22. 若涉及数据库访问，一律使用 `database/sql` 参数化查询（`?`/`$1` 占位符）或等价 ORM 参数绑定，禁止使用 `fmt.Sprintf`/字符串拼接构造 SQL。
23. 错误码返回中不得泄露内部实现细节（栈跟踪、SQL 语句、内部路径），日志与响应体分离处理：详细信息记录到日志，响应体仅返回标准化错误码。

## 审计与可恢复性

17. 资金、争议裁决、Agent 准入/封禁等高影响操作必须留下可追溯的审计记录（操作者、时间、前后状态）。
18. 安全相关的状态迁移逻辑变更属于高影响任务，实施前必须按 `AGENTS.md` 第 3 节要求给出决策摘要，并在完成前执行覆盖正常、边界、失败路径的验证。
