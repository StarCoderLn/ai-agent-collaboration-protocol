# V0 匹配与候选列表 — 需求规格

## 概述

实现「分类过滤 → 资格过滤 → 标签匹配 → 规则排序」的可解释匹配链路，生成候选 Agent 列表与可追溯的 `JobDistributionRecord`。对应 PRD FR-M01。

> 2026-08-30 正式工作流映射：每个节点按分类、标签、预算和可用性执行本 feature 的
> 权威匹配，持久化候选快照与排序依据。平台最多向用户展示 3 个候选供选择，但只派发
> 最终分配的 1 个 Agent；旧固定候选体验页已经删除。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 需求版本

| 日期       | 版本 | 说明     |
| ---------- | ---- | -------- |
| 2026-08-20 | v1   | 初始需求 |
| 2026-08-20 | v2   | "试运行标识"改为"新入驻标识"，对应 [[3.agent-health-lifecycle]] v5 的受控上线期机制 |

## 用户故事

- 作为发布者，我想要看到候选 Agent 列表并理解为什么这些 Agent 被推荐（匹配标签、报价、预计时长、评分、历史完成量），以便做出选择或开启自动分配。
- 作为平台，我想要每次匹配都留下可追溯的记录（候选集、过滤原因、排序结果、规则版本），以便复现历史匹配结果和排查匹配异常。
- 作为发布者，当没有候选 Agent 时，我想要知道主要限制条件是什么，以便调整任务后重新匹配。

## 功能需求

1. [F-001] 匹配链路：分类过滤 → 资格过滤（预算、Agent 健康状态、准入状态、截止时间等硬约束，复用 [[7.task-visibility-and-mode]] 的 `ValidateHardConstraints`）→ 标签匹配 → 规则排序。
2. [F-002] `[v2 修改]` 候选展示字段：匹配标签、报价、预计时长、评分、历史完成量、**新入驻标识**（原"试运行标识"，处于 [[3.agent-health-lifecycle]] 定义的受控上线期时展示，与"是否通过沙箱准入"无关——能出现在候选列表里的 Agent 本来就已经是 `active` 状态，早已通过沙箱准入）。
3. [F-003] 无候选处理：说明主要限制条件（如「无 Agent 满足预算」「无 Agent 具备该标签」），并允许发布者修改任务后触发重新匹配。
4. [F-004] 可复现性：相同输入和相同规则版本必须产生相同的候选集合与排序结果；每个候选展示简短匹配理由。
5. [F-005] `JobDistributionRecord`：每次匹配持久化任务快照、候选集、过滤原因、特征值、排序结果、规则版本、最终选择。
6. [F-006] 排序规则版本化：排序权重（匹配度、质量、价格、响应速度、负载、历史完成量）可配置且有版本号，具体权重数值待产品确认。

## 非功能需求

- 性能: 从任务进入「待匹配」到生成候选列表的耗时目标 P95 < 5 秒（对应 PRD MVP 成功指标「平均匹配耗时」，具体目标值待产品定义，本 feature 先满足内部技术目标）。
- 数据源: 分类、标签存储在 PostgreSQL，初期不为标签检索引入独立数据库（PRD 明确要求），避免过早引入向量库等基础设施。

## 验收标准

- [x] [AC-001] 不满足预算、不可用（未过审/暂停/下架）或无法按时交付（预计时长超过截止时间）的 Agent 不出现在候选列表中。
- [x] [AC-002] `[v2 修改]` 候选项展示匹配标签、报价、预计时长、评分、历史完成量和新入驻标识，且信息与 Agent 当前档案一致。
- [x] [AC-003] 无候选时提示具体限制条件，且修改任务字段后可重新触发匹配并生成新的 `JobDistributionRecord`。
- [x] [AC-004] 用相同任务快照和相同规则版本重复执行匹配，得到完全相同的候选集合与排序结果。
- [x] [AC-005] 每次匹配的 `JobDistributionRecord` 可查询到完整的候选集、过滤原因、特征值、排序结果和规则版本。

## 依赖

- [[3.agent-health-lifecycle]]：候选过滤依赖 Agent 状态（仅 `active` 状态可进入候选）。
- [[6.escrow-sync-and-wallet]]：任务需先进入「待匹配」状态（资金已确认托管）才能触发匹配。
- [[7.task-visibility-and-mode]]：复用其硬约束校验函数与分配模式配置。

## 开放问题

- 排序权重的具体数值待产品确认（PRD §14 P1-2），当前以可配置项 + 默认权重实现，避免权重未定阻塞匹配链路结构开发。
- 候选可视化的脑图式展示（PRD §8.2）「是否纳入 MVP 取决于设计与开发成本评估」，本次切分**不将脑图可视化纳入本 feature 的任务清单**，仅实现列表模式（满足详细比较、移动端、无障碍访问的要求）；脑图视图作为后续设计评估通过后的独立任务补充。
