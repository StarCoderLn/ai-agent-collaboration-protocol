# Agent 注册与凭证管理 — 需求规格

## 概述

Agent 提供者创建并维护 Agent 档案，配置平台调用凭证，凭证加密存储且写入后不可明文读取。对应 PRD FR-A01。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 用户故事

- 作为 Agent 提供者，我想要填写名称、分类、能力描述、标签、报价等信息创建 Agent 档案，以便平台能发现并派发任务给我的 Agent。
- 作为 Agent 提供者，我想让登录钱包继续证明 Agent 所有权，同时自行指定结算收款钱包，以便收入进入独立运营地址而不改变管理权限。
- 作为 Agent 提供者，我想要安全地配置调用凭证，并确信它不会被任何人（包括我自己）再次明文查看，以便降低泄露风险。
- 作为运营人员，我想要每次注册和配置变更都有审计记录，以便追溯异常配置的来源。

## 功能需求

1. [F-001] `[v6 修改]` 创建 Agent 档案：必填字段为名称、服务分类、能力描述、技能标签、计价方式、报价、**所有者钱包、收款钱包**、服务地址、认证配置、邮箱。服务分类必须从任务发布共用的受控分类树选择；分类下拉隐藏仅用于组织的父级节点和层级路径，只展示简明的可执行末级服务。技能标签既可选择平台推荐词条，也可由用户输入自定义标签；两种来源统一小写、压缩空格和去重，最多 10 个、单个最多 32 个字符，并以规范化后的精确交集参与匹配。所有者钱包必须等于 SIWE 会话地址；收款钱包允许不同，只用于结算，不赋予管理权限。
2. [F-002] 认证凭证加密存储：凭证保存后不可再次以明文形式读取，仅支持整体替换（覆盖写）。
3. [F-003] 提交前校验：缺少必填项或字段格式错误（如钱包地址格式、服务地址非合法 URL）时不可提交，并明确标出具体原因字段。
4. [F-004] 注册与配置变更审计：每次创建、编辑、凭证替换都写入审计日志，记录操作者、时间、变更前后摘要（不含明文凭证）。
5. [F-005] Agent 档案编辑：提供者可修改非钱包资料；所有者钱包换绑仍走 [[16.agent-wallet-rebind]]，收款钱包本轮只在注册时配置，后续修改需独立的高风险确认与审计入口。

## 非功能需求

- 性能: 注册提交接口 P95 响应时间 < 500ms（不含外部连通性检查，连通性检查属于 feature 3）。
- 安全: 凭证使用应用层加密（非仅数据库层加密），密钥管理与业务数据库分离；日志与错误信息不得包含凭证明文或密文片段。
- 兼容性: 服务地址字段需同时支持 Agent 使用不同开发框架（Mastra/LangChain/LangGraph）部署的 HTTP(S) 端点，协议层复用 feature 1 的认证规范。

## 验收标准

- [ ] [AC-001] 缺少必填字段时前端和后端均拒绝提交，并分别标出具体缺失字段。
- [ ] [AC-006] `[v3 新增]` 邮箱格式非法时拒绝提交；邮箱字段可编辑（不像钱包地址那样锁定），编辑邮箱本身不触发换绑相关流程。
- [ ] [AC-002] 凭证保存成功后，任何读取接口（含管理员接口）都不能返回明文或可逆密文，只能返回「已配置/未配置」状态与 `key_version`。
- [ ] [AC-003] 创建、编辑、凭证替换三类操作均在 `audit_logs` 表中留下可查询记录。
- [ ] [AC-004] `[v4 澄清]` 所有者钱包 `provider_wallet_address` 一经创建，本 feature 的编辑接口拒绝直接修改；换绑必须走 [[16.agent-wallet-rebind]] 的独立流程，不得把可配置的收款钱包误当作所有者身份。
- [ ] [AC-005] 重复提交同一注册表单（如网络重试）不会创建重复 Agent 档案（依赖 feature 1 的幂等键规范）。
- [ ] [AC-007] `[v4 新增]` 收款钱包与已认证所有者钱包不同时仍可创建；所有者权限继续绑定 `provider_wallet_address`，普通验收和仲裁释放均向 `payout_wallet_address` 结算。
- [x] [AC-008] `[v6 修改]` Agent 上架与任务发布使用同一个“服务分类/技能标签”组件、同一平台推荐数据源和相同单选/多选/自定义输入交互；分类下拉仅展示不带层级路径的可执行末级服务，推荐与自定义标签都进入两端现有的 `tags` 字段。

## 依赖
