# Agent 注册与凭证管理 — 需求规格

## 概述

Agent 提供者创建并维护 Agent 档案，配置平台调用凭证，凭证加密存储且写入后不可明文读取。对应 PRD FR-A01。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 用户故事

- 作为 Agent 提供者，我想要填写名称、分类、能力描述、标签、报价等信息创建 Agent 档案，以便平台能发现并派发任务给我的 Agent。
- 作为 Agent 提供者，我想让登录钱包继续证明 Agent 所有权，同时自行指定结算收款钱包，以便收入进入独立运营地址而不改变管理权限。
- 作为 Agent 提供者，我想直接填写现有 Agent 的执行地址，并按现有服务需要选择是否填写访问密钥，不必先安装平台 SDK 或重写协议。
- 作为 Agent 提供者，我想在提交上架前测试平台能否访问我的 Agent，并看到明确失败原因，避免上架后才发现地址或密钥不可用。
- 作为 Agent 提供者，我想要附上少量公开案例帮助用户判断能力，同时不让自行提供的材料被误认为平台已经验证过的履约成绩。
- 作为运营人员，我想要每次注册和配置变更都有审计记录，以便追溯异常配置的来源。

## 功能需求

1. [F-001] `[v13 修改]` 创建 Agent 档案：必填字段为名称、服务分类、能力描述、技能标签、计价方式、单次服务报价、**所有者钱包、收款钱包**和`Agent 执行地址`；`访问密钥`为可选。联系邮箱不参与登录、服务验证或当前自动接单闭环，不再由上架及编辑页面收集。单次服务报价只支持 USDC，最低 1 USDC，使用 6 位最小单位整数存储；它表示 Agent 每完成一次匹配需求的基础报价，成功结算时平台服务费从该收入中扣除。服务分类必须从任务发布共用的受控分类树选择；分类下拉隐藏仅用于组织的父级节点和层级路径，只展示简明的可执行末级服务。技能标签由提供者按 Agent 的真实能力直接输入，页面不展示缺少任务上下文的全量推荐标签墙；输入值统一小写、压缩空格和去重，服务端继续负责同义词归一与禁用词校验，最多 10 个、单个最多 32 个字符，并以规范化后的精确交集参与匹配。所有者钱包必须等于 SIWE 会话地址；收款钱包允许不同，只用于结算，不赋予管理权限。
2. [F-002] `[v13 修改]` 认证凭证加密存储：只有提供者填写`访问密钥`时才创建凭证记录并执行应用层加密；公开快速 Agent 不生成伪造占位密钥。凭证保存后不可再次以明文形式读取，仅支持整体替换。
3. [F-003] `[v13 修改]` 提交前校验：缺少必填项、单次服务报价低于 1 USDC 或字段格式错误时不可提交，并明确标出具体原因字段。完整资料必须先通过真实连接测试；地址或访问密钥变化后，旧测试成功状态立即失效。未建立 SIWE 会话时，唯一主操作先显示“连接钱包后提交”并触发连接；已连接后才允许“提交上架”。
4. [F-004] 注册与配置变更审计：每次创建、编辑、凭证替换都写入审计日志，记录操作者、时间、变更前后摘要（不含明文凭证）。
5. [F-005] Agent 档案编辑：提供者可修改非钱包资料；所有者钱包换绑仍走 [[16.agent-wallet-rebind]]，收款钱包本轮只在注册时配置，后续修改需独立的高风险确认与审计入口。
6. [F-006] `[v10 新增]` 公开案例为可选字段，首次上架最多提交 3 条；每条包含标题、说明、制品类型和公开 HTTP(S) 预览地址。案例与 Agent 档案、凭证、审计及幂等响应处于同一创建事务，任一写入失败时整体回滚。该来源只能标记为“Agent 自行提供”；平台正式任务中已经验收的公开制品由工作流事实单独生成并标记为“平台已验证交付”，两者不得混用。
7. [F-007] `[v13 新增]` 连接测试：仅在有效 SIWE 会话下访问`Agent 执行地址`同域 `/healthz`，不发送任务正文，不触发模型调用。公开 Agent 无密钥可测试；填写密钥时使用 Bearer Token。成功结果展示实际耗时，失败区分鉴权、响应格式与网络错误。

## 非功能需求

- 性能: 注册提交接口 P95 响应时间 < 500ms；连接测试为独立用户操作，不包含在提交接口时延中。
- 安全: 凭证使用应用层加密（非仅数据库层加密），密钥管理与业务数据库分离；日志与错误信息不得包含凭证明文或密文片段。
- 兼容性: 服务地址字段需同时支持 Agent 使用不同开发框架（Mastra/LangChain/LangGraph）部署的 HTTP(S) 端点，协议层复用 feature 1 的认证规范。

## 验收标准

- [x] [AC-001] `[v7 修改]` 缺少必填字段或单次服务报价低于 1 USDC 时前端和后端均拒绝提交，并分别标出具体字段；未连接钱包时主操作只触发 SIWE 连接，不发送 Agent 注册请求。
- [x] [AC-006] `[v11 修改]` 不填写邮箱可以完成 Agent 上架；新上架与编辑页面均不展示邮箱输入项，注册请求不发送邮箱。旧客户端若仍发送非空邮箱，服务端继续校验格式；历史邮箱数据不清空、不伪造。
- [x] [AC-002] 凭证保存成功后，任何读取接口（含管理员接口）都不能返回明文或可逆密文，只能返回「已配置/未配置」状态与 `key_version`。
- [x] [AC-003] 创建、编辑、凭证替换三类操作均在 `audit_logs` 表中留下可查询记录。
- [x] [AC-004] `[v4 澄清]` 所有者钱包 `provider_wallet_address` 一经创建，本 feature 的编辑接口拒绝直接修改；换绑必须走 [[16.agent-wallet-rebind]] 的独立流程，不得把可配置的收款钱包误当作所有者身份。
- [x] [AC-005] 重复提交同一注册表单（如网络重试）不会创建重复 Agent 档案（依赖 feature 1 的幂等键规范）。
- [x] [AC-007] `[v4 新增]` 收款钱包与已认证所有者钱包不同时仍可创建；所有者权限继续绑定 `provider_wallet_address`，普通验收和仲裁释放均向 `payout_wallet_address` 结算。
- [x] [AC-008] `[v9 修改]` Agent 上架与任务发布使用同一个“服务分类/技能标签”组件、同一分类数据源和相同的标签添加、移除及边界提示；分类下拉仅展示不带层级路径的可执行末级服务。页面不展示平台推荐标签墙，用户输入的标签在两端都进入现有 `tags` 字段，并由服务端统一完成规范化与安全校验。
- [x] [AC-009] `[v10 新增]` 上架页可添加、移除最多 3 条公开案例；非法协议、缺少标题或说明、超过数量上限时前后端均拒绝。候选页明确显示案例来源，只有公开 HTTP(S) 地址可生成外链，Agent 自行提供案例不会进入平台已验证统计。
- [x] [AC-010] `[v13 新增]` 上架页保留`Agent 执行地址`与`访问密钥`字段名；访问密钥明确标为可选。只有当前地址和密钥组合通过连接测试后才能提交，异步测试期间修改字段不会被旧响应错误覆盖。
- [x] [AC-011] `[v13 新增]` `http_json` 注册可不带凭证且不触发 KMS、不创建凭证行；未声明模式的历史客户端仍默认 `aicp_hmac` 并要求共享密钥。
