# AI 工作流规划需求

## 目标

需求方发布自然语言目标后，平台生成一份可以理解和修改的多 Agent 工作流草案。用户确认
阶段、输入输出和依赖关系后，平台才逐节点匹配 Agent，并沿用现有选人、托管、执行、验收
和争议流程。

## 功能需求

1. `[F-001]` 任务提交进入 `planning`，同一事务保存可恢复的确定性初始草案。
2. `[F-002]` 发布者可以请求模型重新规划；模型调用不得持有数据库事务。
3. `[F-003]` 草案支持 1～12 个节点和最多 32 条边，拒绝重复节点、未知端点、自环、重复边、孤立节点和环路。
4. `[F-004]` 发布者可以编辑阶段名称、说明、能力、输入输出，增删节点和依赖边。
5. `[F-005]` 每次 AI 或用户保存均追加修订，记录来源、模型、提示词版本和操作者，并通过 version 防止并发覆盖。
6. `[F-006]` 确认操作在一个数据库事务中锁定草案并固化正式 DAG；确认后不能再编辑。
7. `[F-007]` 确认前不得创建候选、冻结报价、托管意图、分配或链上交易。
8. `[F-008]` 模型层通过统一接口支持 DeepSeek 与 OpenAI 配置切换，领域代码不读取厂商密钥或 SDK。
9. `[F-009]` AI 规划只能使用 active Agent 实时声明的分类与输入/输出契约完整组合；确认时再次加锁校验，每个阶段至少有一个可执行 Agent。
10. `[F-010]` 尚未选人和托管的历史错误正式图可以恢复为草案；恢复前必须保存不可变审计快照，存在任何资金或执行事实时拒绝恢复。
11. `[F-011]` 正式图支持逐阶段选人和一键采用全部剩余首选候选；批量操作由服务端读取最新快照，在单事务内全部成功或回滚，且不创建托管意图。

## 验收标准

- DeepSeek 能把真实自然语言需求生成合法 DAG，首次非法输出会被本地校验拒绝并最多修正一次。
- 浏览器可以修改节点、增加阶段、创建依赖、保存修订并确认；确认后显示正式分配关系图。
- 数据库中草案修订可追溯，正式 run/node/edge 与确认版本一致，候选和托管记录仍为零。
- Agent 能力缺失时确认失败并指明受影响阶段；不得先确认、再以空候选状态暴露错误。
- 安全恢复后活动 DAG 与候选派生数据被移除，原计划、DAG、候选、曝光和影子排序事实仍可从恢复快照追溯。
- 旧任务继续读取原正式工作流，不迁移或重写历史资金事实。
- 单选成功自动聚焦下一未选阶段，失败保留当前阶段；批量确认明确展示剩余阶段、首选 Agent 和包含已有冻结报价的最终总价。

## 非目标

- 循环、运行中动态扩图、条件表达式、AI 选择 Agent、AI 决定报价或资金结果。
- 让 LangGraph checkpoint 或前端画布成为任务、交易或资金的权威状态。
