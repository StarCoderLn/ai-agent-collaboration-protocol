# 任务可见性与分配模式 — 需求规格

## 概述

定义任务的私密/公开可见性、手动/自动分配模式、以及人工/机器验收模式的配置与硬约束校验；提供公开任务市场与「我的任务」工作台两个独立页面。对应 PRD FR-T02 与 §8.1。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 用户故事

- 作为发布者，我想要选择任务私密或公开，并在公开前清楚看到市场上实际会展示哪些字段，以便控制信息暴露范围。
- 作为发布者，我想要默认手动选择候选 Agent，仅在明确开启自动分配时才让平台自动选择，并清楚了解自动分配的排序依据和价格上限。
- 作为平台，我想要非确定性 AI 任务默认由发布者验收，只有任务预先配置了机器验收规则才允许自动放款，以避免用户被误导为「Agent 自称完成就自动放款」。

## 功能需求

1. [F-001] 可见性：私密（默认，仅候选/已接单 Agent 可见）与公开（进入任务市场，敏感字段仍按规则隐藏）两种模式。
2. [F-002] 发布前预览：发布者能在托管前预览公开任务实际暴露给市场的字段集合。
3. [F-003] 分配模式：手动选择为默认模式；开启自动分配时必须展示排序依据、价格上限和失败后的处理方式。
4. [F-004] `[v4 修改]` 硬约束：候选不得跳过 Agent 健康状态、准入状态、币种、截止时间和**冷启动期单次报价上限**。发布者填写的整单预算是规划参考，不参与资格过滤；真实结算任务数未达到配置阈值（默认 3）的 Agent 必须比较自身报价与 [[3.agent-health-lifecycle]] 的风险上限，评分样本量不参与该判断。
5. [F-005] 变更限制：可见性和分配模式的变更写入审计日志；Agent 接单后不得直接切换模式。
6. [F-006] 验收模式：非确定性 AI 任务默认由发布者验收，不因 Agent 自报「完成」自动放款；只有任务预先配置了机器验收规则（验收器）时才可单独开启自动验收。
7. [F-007] 页面分离：公开任务市场（支持关键词/分类/标签/状态筛选）与「我的任务」工作台（总任务/待处理/执行中/待验收/已完成/争议中统计）分离展示，统计口径不混用。

## 非功能需求

- 一致性: 可见性字段脱敏规则必须在唯一位置定义（单一权威实现），公开任务市场查询接口和详情接口都调用同一规则，不允许分别实现导致口径不一致。
- 安全: 私密任务的详情接口必须校验请求者是发布者、已接单 Agent 或授权运营人员之一，其余请求一律拒绝。

## 验收标准

- [x] [AC-001] 私密任务的详情不对非授权用户可见（包括未接单的候选 Agent）。
- [x] [AC-002] 公开任务市场列表和详情展示的字段集合与发布者预览时看到的字段集合完全一致。
- [x] [AC-003] 开启自动分配时，界面展示排序依据、价格上限和失败回退方式；未开启时默认走手动选择。
- [x] [AC-004] `[v4 修改]` 候选集合不包含不健康、未过审、币种不符、无法按时交付，或真实结算少于 3 个且自身报价超过冷启动上限的 Agent；达到 3 个结算后即使评分仍少于 20 份也不得继续拦截。
- [x] [AC-005] Agent 已接单的任务，尝试调用切换可见性/分配模式的接口被拒绝。
- [x] [AC-006] 未配置验收器的任务无法开启自动验收；已配置验收器且开启自动验收的任务在 UI 上有明确标识，不与人工验收任务混淆。
- [x] [AC-007] 公开任务市场统计与「我的任务」工作台统计使用不同的数据来源，互不影响。

## 开放问题

- ~~自动分配是否进入 MVP~~ `[2026-08-30 已确认]`：手动为默认模式，自动分配为发布者显式开关；开启时展示排序、价格上限和失败回退，并复用同一套硬约束。
- 通用机器验收（自动放款）的适用任务范围与验收器提供方仍未定：本 feature 只实现「验收器存在性」前置校验。正式 Product Workflow 的中间节点由版本化机器门禁自动推进、最终节点人工验收；该已实现特例不得被扩大解释成所有任务都可自动放款。
