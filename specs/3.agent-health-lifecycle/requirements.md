# Agent 健康检查与生命周期 — 需求规格

## 概述

管理 Agent 从注册到可接单的状态流转（自动验证/可接单/暂停/下架），持续健康检查并在异常时自动暂停派发；新 Agent 的自动准入由 [[15.agent-sandbox-admission]] 提供。对应 PRD FR-A02、FR-A03。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 用户故事

- 作为平台，我想要区分 Agent 认证失败、协议不兼容、连接超时和内部错误，以便针对性地暂停派发或提示提供者修复。
- 作为 Agent 提供者，我想要暂停接单而不影响已接任务的继续执行，以便在维护期间不违约。
- 作为平台，我想要只接受带结构化准入决策 ID 的自动放行事件，以便状态变化可追溯且不能被自由文本理由绕过。

## 功能需求

1. [F-001] 健康检查结果分类：区分认证失败、协议不兼容、连接超时、Agent 内部错误四类（复用 [[1.agent-protocol-contract]] 的错误码）。
2. [F-002] `[v3 修改]` 连续失败自动暂停：**仅统计专门的健康检查探测**（不含真实任务执行中的失败，后者由评分和争议机制治理，不进入本计数器）；**仅认证失败、协议不兼容、连接超时三类计入失败**（`Agent 内部错误`不计入——这是业务逻辑失败，与"平台联系不上/协议不兼容"性质不同，不应触发同一套熔断）；**任意一次健康检查成功，失败计数器立即清零**；连续失败达到可配置阈值后，自动暂停向该 Agent 派发新任务。
3. [F-003] 显式状态机：`自动验证中 → 可接单 → 暂停 → 下架`（暂停可恢复到可接单，下架为终态，需重新注册），非法状态迁移必须被拒绝。
4. [F-004] 未通过自动准入、暂停或下架的 Agent 不出现在公开候选列表中（对接 feature 8 的候选过滤逻辑）。
5. [F-005] 暂停接单不影响已接任务继续执行至完成或超时。
6. [F-006] `[2026-09-04 修订]` 冷启动风险上限：Agent 完成自动准入后，在已验收并结算的真实任务数达到可配置阈值（默认 3）前，其单次冻结报价不得超过平台历史成交金额的较低分位数（默认第 30 百分位）。尚无真实结算记录时展示“新 Agent”；首个真实任务结算后立即移除该标识，但报价限制继续到累计 3 个真实结算任务。沙箱调用、仅接单、失败任务和评分样本均不计入真实结算数；贝叶斯 `prior_weight` 只用于评分置信度，不再控制标识或资金风控。
7. [F-007] `[v10 修改]` 转为正式状态必须携带 [[15.agent-sandbox-admission]] 生成的结构化准入决策 ID，并把系统操作者与证据写入审计日志；正常准入不接受人工自由文本理由，也不提供人工通过或驳回入口。
8. [F-008] `[v4 新增]` 自动恢复：仅**因连续健康检查失败被自动暂停**的 Agent，达到可配置的连续成功阈值后自动恢复为可接单状态，无需人工介入；**提供者主动发起的暂停不适用自动恢复**，必须由提供者显式调用恢复接口，防止"维护中"被健康检查探测误判为"已恢复"而提前把任务派过去。
9. [F-009] `[v9 新增]` 接入模式适配：`aicp_hmac` 健康探测继续发送 AICP v1 签名头；`http_json` 调用同域 `/healthz`，有访问密钥时发送 Bearer Token，无密钥时不发送认证头。两种模式共享相同结果分类、暂停和恢复状态机。

## 非功能需求

- 性能: 健康检查任务对单个 Agent 的检查间隔可配置，默认 5 分钟一次，不因检查任务本身拖慢派发链路。`[v4]` 检测延迟目标：约 10-15 分钟发现异常并暂停（间隔 5 分钟 × 失败阈值 3 次）；约 10 分钟确认恢复并解除暂停（间隔 5 分钟 × 恢复阈值 2 次）。恢复阈值刻意设置得比失败阈值更保守（需要更多次确认），是为了避免 Agent 在故障边缘反复抖动时暂停/恢复状态来回跳变（flapping）。
- 安全: 自动准入事件只能由内部服务认证边界调用；提供者重试由 Business API 从 SIWE 会话解析归属，不能信任客户端自报身份。
- 兼容性: 健康检查从 Agent 的权威接入模式选择认证方式，历史 HMAC 行为不变；所有模式复用同一超时分类和生命周期状态机。

## 验收标准

- [x] [AC-001] 健康检查失败时，返回的失败原因可归类到四类错误码之一，不是笼统的“失败”。
- [x] [AC-002] 连续失败达到阈值后，该 Agent 不再出现在新的候选列表中，但不影响其已接的进行中任务。
- [x] [AC-002a] `[v3 新增]` `Agent 内部错误`类的健康检查结果不计入连续失败计数；真实任务执行失败不计入本计数器（只统计专门的健康检查探测）；中间穿插一次健康检查成功会将计数器清零，不是"最近 N 次里失败次数达标"这种滑动窗口口径。
- [x] [AC-003] 非法状态迁移（如从「下架」直接迁移到「可接单」）被拒绝并返回明确错误。
- [x] [AC-004] `[v11 修改]` 0 个真实结算任务的 Agent 展示“新 Agent”；完成首个真实结算后标识消失，累计达到配置阈值（默认 3）后解除冷启动报价限制。评分不足 20 份仍只显示低置信度，不得重新出现“新 Agent”或延长报价限制。
- [x] [AC-005] 每次状态迁移（含自动暂停、自动准入通过）在 `audit_logs` 中留痕，记录触发条件与操作者（自动触发记录为系统操作者）。
- [x] [AC-006] `[v4 新增]` 因连续失败自动暂停的 Agent，达到连续成功阈值后自动恢复为可接单，无需人工操作；同样的健康检查恢复对提供者主动暂停的 Agent 不产生任何状态变化。
- [x] [AC-007] `[v4 新增]` 提供者可对自己主动暂停的 Agent 调用恢复接口重新上架；对因健康检查自动暂停的 Agent 调用同一接口应被拒绝并提示"等待自动恢复或联系运营"，防止提供者绕过健康状态直接强行恢复一个仍不健康的 Agent。
- [x] [AC-008] `[v9 新增]` 快速 Agent 的公开与 Bearer `/healthz` 探测均可成功；未知模式被判定为协议不兼容，且不会静默回退成无认证请求。
