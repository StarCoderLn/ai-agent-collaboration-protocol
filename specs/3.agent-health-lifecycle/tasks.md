## 任务列表

### 功能 1: 状态机

- [x] T-001: 定义 Agent 状态枚举、合法迁移表与迁移事件类型（Go，可辨识联合），并编写 `agent_health_checks`、`agent_status_config` 表 migration ~30min

### 功能 2: 健康检查

- [x] T-002: 实现健康检查定时任务（按 Agent 调度，依据 `integration_mode` 使用 HMAC 或可选 Bearer Token 调用同域 `/healthz`，分类结果写入） ~30min
- [x] T-003: 实现健康检查结果处理（`[v3]` 连续失败计数与自动暂停：仅认证失败/协议不兼容/连接超时三类计数，`Agent 内部错误`记录但不计数，任意一次成功清零失败计数器；`[v4]` 连续成功计数与自动恢复：仅当 `pause_reason=health_check` 时生效，达到 `resume_success_threshold` 触发 `AutoResumeHealthCheck`）；仅统计健康检查探测，不含真实任务失败 ~30min

### 功能 3: 准入状态与操作 API

- [x] T-004: 实现准入状态迁移（`[v9]` 只接受 Feature 15 的结构化自动评测证据；原临时人工通过/驳回 API 已移除） ~30min
- [x] T-005: 实现提供者暂停/恢复/下架 API（校验合法迁移，不影响已接任务；`[v4 新增]` 恢复接口仅 `pause_reason=manual` 放行，`pause_reason=health_check` 返回 `RESUME_REQUIRES_HEALTH_RECOVERY`） ~30min

### 功能 4: 前端

- [x] T-006: 实现提供者视角的 Agent 状态展示（`[2026-09-04]` 零真实结算显示“新 Agent”，提供者弱提示 3 单冷启动进度，不公开内部统计术语）与暂停/恢复/下架操作入口（`pause_reason=manual` 才展示恢复按钮） ~30min
- [x] T-007: ~~实现运营审核后台最小页面~~ `[v9 已替换]` 自动准入上线后删除临时审核后台，提供者在“我的 Agent”查看自动验证进度与失败重试

### 集成与测试

- [x] T-008: 编写测试：非法状态迁移拒绝、自动暂停不影响已接任务、审核审计留痕、`Agent 内部错误`不计入连续失败、成功探测清零计数器、真实任务失败不影响健康检查计数、连续成功自动恢复、提供者无法强制恢复健康检查暂停、手动暂停可恢复，以及快速 Agent 公开/Bearer 健康探测和未知模式拒绝 ~30min

## 风险点

- 阈值与风险上限当前为占位默认值（见 requirements.md 开放问题），若产品确认的数值差异较大，可能需要重新评估自动暂停对 Agent 接单成功率指标的影响，但不影响状态机结构本身。
