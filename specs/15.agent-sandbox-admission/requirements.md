# 新 Agent 沙箱准入 — 需求规格

## 概述

新 Agent 通过基础注册审核后，平台自动发起 3 次标准化沙箱测试调用，运营基于预定义的是/否清单对产出做客观判定，全部通过才转为正式可接单状态。对应 PRD FR-A03、§14 P0-7（已确认采用「沙箱调用 3 次」方案）。

本 feature 是 `/yd:prd --change` 追加的 feature：原 [[1.agent-protocol-contract]]、[[3.agent-health-lifecycle]] 中将其列为开放问题，经用户确认后拆出独立 feature（沙箱准入是围绕"测试调用 + 清单判定"的独立功能闭环，与 3 的持续性健康检查/状态机是不同性质的知识，不适合塞进已满 8 个任务上限的 feature 3）。

## 项目信息

- 架构类型: 多服务架构

## 用户故事

- 作为平台，我想要用标准化的测试任务和客观清单去评估新 Agent，而不是让运营对开放式产出做主观质量打分，以便判断结果可复核、可审计，且不要求运营具备该 Agent 所在领域的专业知识。
- 作为运营人员，我想要面对的是一份是/否清单而不是"这个输出好不好"的开放问题，以便我能快速、一致地做出判断。
- 作为 Agent 提供者，我想要清楚知道平台会用什么样的测试任务评估我的 Agent，以便提前确认我的 Agent 能正确处理。

## 功能需求

1. [F-001] 标准化测试任务模板：平台为每个能力分类预先定义固定的测试任务输入和对应的判定清单，版本化管理。
2. [F-002] 沙箱调用执行：Agent 完成基础注册审核（[[2.agent-registration]]）后，平台自动向其发起 3 次标准化调用，调用标记为 `call_type=sandbox`（复用 [[1.agent-protocol-contract]] 的沙箱标记位），不产生真实资金和真实任务记录；同一轮的平台重试复用稳定 `round_id` 和调用幂等键，提供者修复后的重测使用新的 `round_id`。
3. [F-003] 技术指标自动记录：每次沙箱调用自动记录协议合规性（是否正确响应、格式是否合法）、响应延迟、是否报错等客观技术指标，不需要人工判断这部分。
4. [F-004] 清单式人工判定：运营基于测试任务模板预定义的是/否清单（如「是否跑题」「格式是否符合要求」「是否有明显报错/空白/乱码」「是否明显抄袭/套用模板」）逐条勾选，不做开放式主观打分。
5. [F-005] 判定驱动准入：3 次沙箱调用的清单判定全部通过时，触发 [[3.agent-health-lifecycle]] 的 `TransitionAgentStatus`（`AdminApprove` 事件），Agent 从试运行转为可接单；未全部通过时保持试运行状态，Agent 提供者可在修复后重新发起沙箱测试。
6. [F-006] 沙箱记录留痕：测试任务内容、调用产出、技术指标、清单判定结果、判定人均写入审计记录，可追溯。

## 非功能需求

- 一致性: 同一测试任务模板产生的判定清单在所有沙箱调用之间保持一致，不因运营个人理解差异而变化（清单项本身是客观陈述句，不是评分维度）。
- 安全: 沙箱调用不得产生真实资金流转，也不进入 [[9.dispatch-and-acceptance]] 的正式派发与分配路径。
- 可追溯: 沙箱调用产出物需保留（或保留引用），供后续复核或申诉时查阅。

## 验收标准

- [ ] [AC-001] 新 Agent 完成基础注册审核后，系统自动发起 3 次标记为 `sandbox` 的测试调用，不需要人工手动触发。
- [ ] [AC-002] 每次沙箱调用的技术指标（协议合规、延迟、是否报错）自动记录，无需人工填写。
- [ ] [AC-003] 运营的判定操作只能勾选预定义清单项，不能提交清单之外的自由文本作为通过/拒绝的唯一依据。
- [ ] [AC-004] 3 次调用的清单判定全部通过后，Agent 状态自动从试运行迁移为可接单，且该迁移记录可追溯到具体的判定记录 ID。
- [ ] [AC-005] 未全部通过时 Agent 保持试运行状态，且提供者可重新发起一轮沙箱测试（不要求重新完成整个注册流程）。
- [ ] [AC-006] 沙箱调用产生的记录不出现在 Agent 的正式任务历史或评分统计中（复用 [[1.agent-protocol-contract]] 的 `call_type` 过滤）。

## 依赖

- [[1.agent-protocol-contract]]：复用签名认证与 `call_type=sandbox` 标记位。
- [[2.agent-registration]]：沙箱测试的前置条件是 Agent 已完成基础注册审核。
- [[3.agent-health-lifecycle]]：判定通过后调用其 `TransitionAgentStatus`（`AdminApprove` 事件），复用同一状态机，不新建一套 Agent 状态。

## 开放问题

- 各能力分类的具体测试任务内容和清单项细节待产品/运营团队按分类逐一定义（PRD 未给出具体测试题目）；MVP 通用清单模板已由 T-001 录入（协议合规、格式正确、无报错、不跑题、不抄袭套版），分类专属测试任务仍作为后续数据优化项，不阻塞本 feature 的流程结构开发。
