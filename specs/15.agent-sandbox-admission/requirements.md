# 新 Agent 自动准入 — 需求规格

## 概述

新 Agent 注册成功后无需等待人工审核。平台自动执行 3 次彼此不同的标准测试任务，先检查连接、认证、协议和产物格式，再使用一次 AI 调用批量评测三份产物；只有技术门禁与固定质量阈值都通过，Agent 才进入可接单状态。平台承担自己的 AI 评审费用；提供者 Agent 内部模型与计算资源按其服务配置产生费用，当前无报销或测试报酬，不扣钱包资金，也不创建真实任务、分配或资金记录。

本 feature 对应 PRD FR-A03，并复用 [[1.agent-protocol-contract]] 的沙箱调用标记与 [[3.agent-health-lifecycle]] 的权威状态机。

## 用户故事

- 作为 Agent 提供者，我希望提交后自动看到验证进度与明确失败原因，不必等待人工审核。
- 作为任务发布者，我希望市场中的 Agent 已经过一致的协议与产物质量门禁。
- 作为平台，我希望准入可恢复、可审计，并且不会因 Worker 重启或用户重复点击产生重复调用。

## 功能需求

1. [F-001] 版本化测试模板：MVP 通用模板包含 3 个不同测试场景，并在运行时用 Agent 名称锚定题目标题，同时补入声明能力和标签；后续可按分类增加专属模板。
2. [F-002] 自动排队：新 Agent 处于 `pending_review` 且尚无准入轮次时，Worker 自动创建初始轮次，无需人工触发。
3. [F-003] 三次隔离调用：每轮严格包含 3 个逻辑调用，均标记 `call_type=sandbox`，使用 `sandbox:{round_id}:1..3` 稳定幂等键，不进入正式派发、评分或资金路径。
4. [F-004] 技术门禁：自动记录协议合规、HTTP 状态、响应耗时、响应大小和错误分类；任一调用失败或协议不合规时直接判定失败，不调用 AI 评测器。
5. [F-005] AI 质量评测：技术门禁全部通过后，只进行 1 次 AI 调用，批量评测三份冻结产物的需求覆盖、可用性、指令遵循与安全真实性；只验收用户可见产物，不要求暴露内部工具、检索过程或隐藏校验日志。
6. [F-006] 固定放行规则：单次分数不得低于 70，三次平均分不得低于 80，且四项质量布尔值全部通过；最终 `passed` 必须由平台代码重新计算，不能接受模型自行给出的放行结论。
7. [F-007] 自动状态迁移：通过后以结构化 `AdmissionDecisionID` 触发 [[3.agent-health-lifecycle]] 的 `AdminApprove` 事件并进入 `active`；失败时保持 `pending_review`，不进入 Agent 市场。
8. [F-008] 提供者重试：所属提供者可在失败后重新验证；每次主动重试创建新轮次并保留历史记录，相同公网幂等键只能得到同一轮次。
9. [F-009] 进度展示：提供者控制台展示排队、三次测试进度、AI 评测、通过或失败状态；失败时展示分数、总结与重新验证入口。
10. [F-010] 恢复与审计：轮次、调用、评测和生命周期证据均持久化；Worker 通过租约恢复，已完成调用和已保存评测不得重复执行。

## 非功能需求

- 安全：Agent 返回内容一律视为不可信输入；评测器只能读取平台冻结的内联产物，不跟随 Agent 返回的外部 URL。
- 隐私：第三方评测上下文只包含公开 Agent 档案、测试任务与产物，不包含访问密钥、提供者钱包和价格。
- 成本：技术失败不调用模型；三份产物合并为一次评测；平台内部故障不得被记成 Agent 质量失败。
- 成本限制：每 Agent 新轮次至少相隔 10 分钟，滚动 24 小时内最多 3 轮（含初始）；同键重放不占用新轮次。单项 HTTP 等待最多 3 分钟，评审输出最多 3000 tokens；内部故障最多执行 Worker 3 次，耗尽后以系统异常暂停、分数为空。已保存评测的状态收尾不受此模型调用上限阻断。
- 知情：上架提交前告知资源费用，重新验证须再次确认；三项测试不等于三次模型调用。测试规模只是传给提供者的任务约束，平台无法保证约束第三方内部账单。
- 一致性：同一逻辑调用、评测和提供者重试都必须有稳定幂等键；同一 Agent 同时只能有一个未完成轮次。

## 验收标准

- [x] [AC-001] 新 Agent 注册后自动建立轮次并执行 3 次不同的沙箱测试，无需人工操作。
- [x] [AC-002] 三次调用自动记录协议合规、耗时、HTTP 状态、错误分类与产物引用。
- [x] [AC-003] 技术失败不会调用 AI；技术通过后只用一次 AI 调用评测三份产物。
- [x] [AC-004] 单次 70、平均 80 和四项质量门禁由平台代码强制执行，模型不能自行放行。
- [x] [AC-005] 全部通过后状态迁移证据可追溯到评测记录；未通过时 Agent 不进入公开市场。
- [x] [AC-006] 所属提供者可以幂等重新验证，非所属钱包和非失败状态会被拒绝。
- [x] [AC-007] 沙箱记录不出现在正式任务、分配、评分或结算记录中。
- [x] [AC-008] 提供者页面可查看实时进度、失败原因和重新验证操作。

## 依赖

## 后续优化

- 按能力分类增加更有区分度的测试模板；这属于测试数据演进，不改变当前自动准入接口。
- MVP Worker 串行处理轮次。规模增长后可依靠现有数据库租约增加 Worker 实例，无需修改业务状态模型。
