# 争议与人工仲裁 — 需求规格

## 概述

支持双方发起争议、提交证据，由平台授权仲裁员或 YD DAO 仲裁小组做出支付、部分支付、退款决定。资金在争议期间冻结，决定的链上执行需等待确认后才展示为已完成。对应 PRD FR-R02。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 需求版本

| 日期       | 版本 | 说明     |
| ---------- | ---- | -------- |
| 2026-08-20 | v1   | 初始需求 |
| 2026-08-30 | v2   | 同步当前平台仲裁权限、部分支付能力和未来 YD DAO 仲裁边界 |
| 2026-09-02 | v3   | 落地 YD 质押成员、利益冲突分案、DAO 多数投票和带证据摘要的多 Agent 资金执行 |

## 用户故事

- 作为发布者或 Agent 提供者，我想要在规定时限内发起争议、选择原因并提交证据，以便在结果或执行有分歧时寻求平台裁决。
- 作为仲裁员，我想要查看双方证据并做出支付、部分支付或退款决定，且理由与操作可审计，以便公正处理并留痕。
- 作为平台，我想要争议创建后立即冻结相关资金，不因超时或其他流程被自动结算，以便保护双方在裁决前的权益。
- 作为 YD 持有者，我想通过链上质押成为可验证的 DAO 仲裁成员，并在无利益冲突时参与案件投票。

## 功能需求

1. [F-001] 争议发起：双方可在规定时限内选择原因并提交证据。
2. [F-002] 资金冻结：争议创建后冻结相关资金（阻止 [[5.escrow-contract-ethereum]] 的 `release`/`refund` 被非仲裁流程触发），不得自动结算。
3. [F-003] 状态可见：双方可查看争议状态、证据截止时间和最终决定。
4. [F-004] `[v2 修改]` 仲裁决定：MVP 中持久化授权的 `arbitrator` 可做出支付、部分支付或退款决定。是否在正式运营环境开放部分支付、二次申诉和仲裁费，仍需产品与合规在上线前确认。
5. [F-005] 可审计：仲裁理由、证据、操作者和资金执行结果必须可审计。
6. [F-006] 执行确认：链上交易未确认前，不得向用户展示「仲裁决定已执行」。
7. [F-007] `[v3 新增]` DAO 资格：用户将不少于平台门槛的 YD 锁入 `ArbitrationDAO` 后获得候选资格；申请退出后立即停止新分案，冷静期结束才能取回全部 YD。服务端只接受经确认的目标合约交易与对应区块状态，不信任浏览器自报余额。
8. [F-008] `[v3 新增]` 自动分案：每个争议建立独立 DAO 轮次，从合格成员中排除发布者、所有已接单 Agent 的运营钱包及收款钱包；候选不足时保持“等待成组”，不得静默降低小组人数。
9. [F-009] `[v3 新增]` 多数投票：V1 固定三人小组、两票同类裁决形成多数；重复投票和非小组成员投票必须拒绝。部分结算比例取多数票中位数，裁决、投票和资金计划原子写入。
10. [F-010] `[v3 新增]` 多 Agent 资金执行：释放额按各阶段冻结报价比例分配，最小单位舍入余数归入最后一条分账，确保释放额与退款额守恒；全额退款走专用链上入口，部分/全部释放走原子工作流分账。

## 非功能需求

- 一致性: 争议冻结状态必须与 [[6.escrow-sync-and-wallet]] 的资金操作互斥，不允许争议进行中同时有未经仲裁授权的结算/退款发生。
- 可审计: 仲裁决定的证据、理由、操作者、执行结果需要长期保留，不因后续数据清理而丢失。

## 验收标准

- [x] [AC-001] 争议创建后，该任务对应的资金无法通过正常验收/超时流程被结算或退款。
- [x] [AC-002] 双方均可查询到当前争议状态、证据提交截止时间。
- [x] [AC-003] 仲裁员做出决定后，在链上交易确认前，界面展示「处理中」而非「已完成」。
- [x] [AC-004] 每个仲裁决定的理由、提交的证据、操作仲裁员、最终资金执行结果均可在审计记录中查询到。
- [x] [AC-005] 非仲裁员角色无法调用仲裁决定接口。
- [x] [AC-006] 未达到 YD 门槛、已申请退出或交易证据不属于当前钱包时，不能获得 DAO 仲裁资格。
- [x] [AC-007] 发布者、Agent 运营钱包和收款钱包不会被分配到关联案件；成员不足时案件保持可恢复等待状态。
- [x] [AC-008] 两票多数最多生成一份裁决和一份资金 outbox；重复投票、并发最后一票及非法比例不会产生重复结算。
- [x] [AC-009] DAO 与平台仲裁使用同一套多 Agent 分账规则；链上确认前资金持续冻结，确认后任务、争议、裁决和托管状态在同一事务收敛。

## 依赖

- [[11.execution-tracking-and-delivery]]：争议可能在执行中或待验收阶段发起。

## 开放问题

- MVP 权限边界已落地：只有 `platform_actor_roles(role='arbitrator')` 中的地址可以裁决，支持支付、部分支付和退款；当前不实现二次申诉，也不收仲裁费。正式运营是否开放部分支付、申诉和仲裁费仍待产品与合规确认。
- DAO V1 已实现资格质押、退出冷静期、利益冲突排除、三人分案、两票多数和资金执行。仲裁奖励、恶意投票罚没、二次申诉和正式运营合规规则仍未实现；公共测试网上线与第三方合约审计完成前不得把本地验证表述为生产可用。
