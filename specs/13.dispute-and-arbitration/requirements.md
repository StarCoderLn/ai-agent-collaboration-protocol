# 争议与人工仲裁 — 需求规格

## 概述

支持双方发起争议、提交证据，由平台授权仲裁员或 YD DAO 仲裁小组做出支付、部分支付、退款决定。资金在争议期间冻结，决定的链上执行需等待确认后才展示为已完成。对应 PRD FR-R02。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 用户故事

- 作为发布者或 Agent 提供者，我想要在规定时限内发起争议、选择原因并提交证据，以便在结果或执行有分歧时寻求平台裁决。
- 作为仲裁员，我想要查看双方证据并做出支付、部分支付或退款决定，且理由与操作可审计，以便公正处理并留痕。
- 作为平台，我想要争议创建后立即冻结相关资金，不因超时或其他流程被自动结算，以便保护双方在裁决前的权益。
- 作为 YD 持有者，我想通过链上质押成为可验证的 DAO 仲裁成员，并在无利益冲突时参与案件投票。

## 功能需求

1. [F-001] 争议发起：双方可在规定时限内选择原因并提交证据。
2. [F-002] 资金冻结：争议创建后冻结相关资金（阻止 [[5.escrow-contract-ethereum]] 的 `release`/`refund` 被非仲裁流程触发），不得自动结算。
3. [F-003] 状态可见：双方可查看争议状态、证据截止时间和最终决定。
4. [F-004] `[v2 修改]` 仲裁决定：MVP 中持久化授权的 `arbitrator` 可做出支付、部分支付或退款决定。是否在正式运营环境开放部分支付、二次申诉和仲裁费，仍需产品与合规在上线前确认。
5. [F-005] 可审计：仲裁理由、证据、操作者和资金执行结果必须可审计。
6. [F-006] 执行确认：链上交易未确认前，不得向用户展示「仲裁决定已执行」。
7. [F-007] `[v3 新增]` DAO 资格：用户将不少于平台门槛的 YD 锁入 `ArbitrationDAO` 后获得候选资格；申请退出后立即停止新分案，冷静期结束才能取回全部 YD。服务端只接受经确认的目标合约交易与对应区块状态，不信任浏览器自报余额。
8. [F-008] `[v3 新增]` 自动分案：每个争议建立独立 DAO 轮次，从合格成员中排除发布者、所有已接单 Agent 的运营钱包及收款钱包；候选不足时保持“等待成组”，不得静默降低小组人数。
9. [F-009] `[v3 新增]` 多数投票：V1 固定三人小组、两票同类裁决形成多数；重复投票和非小组成员投票必须拒绝。部分结算比例取多数票中位数，裁决、投票和资金计划原子写入。
10. [F-010] `[v3 新增]` 多 Agent 资金执行：释放额按各阶段冻结报价比例分配，最小单位舍入余数归入最后一条分账，确保释放额与退款额守恒；全额退款走专用链上入口，部分/全部释放走原子工作流分账。

## 非功能需求

### v4 新案补充需求

- [F-011] 独立 `ArbitrationCases` 是裁决权威，首审 3 人、一次终审 5 人；申诉窗口不得触发付款，平台内部角色也不能绕过。
- [F-012] Chainlink VRF v2.5 从冻结的合格候选中抽样；候选不足不得降组，请求后不得换名单或重抽，终审排除首审成员。
- [F-013] 首审无多数免费升级终审；终审至少三票时按有效比例中位数裁决。参与不足或全案超时进入有限恢复期，受权角色可提交理由承诺裁决；恢复期结束后任何人都能执行部署时公开的兜底比例，禁止永久冻结。
- [F-014] YD 不提供无条件公共申领。启动期按以下权威事实发放：验证新用户 5 YD、真实资金托管需求 5 YD、需求成功完成后发布者 15 YD、Agent 验证通过 10 YD、Agent 首次成功交付额外 15 YD、Agent 每次成功交付 20 YD、有效仲裁投票 10 YD；单钱包活动上限 100 YD。首次交付可同时获得首次额外奖励和每次交付奖励。空需求或未经验证的 Agent 上架不得直接获奖。独立奖励池预充值，不使用任务预算或成员质押。
- [F-015] 文字及附件引用生成原始承诺并追加保存，支持当事人链上锚定。新上传文件必须保存实际字节及 SHA-256，提交后禁止修改/删除，授权下载时重新校验摘要；单库保存不代替异地备份与恢复演练。
- [F-016] 未迁移/未部署/未配置不得伪造成功；旧案继续原流程，新案拒绝降级为旧版立即结算。
- [F-017] 钱包交易超时或报错不得直接视为失败；只有规范确认的回滚回执及匹配的原始调用可开放用户重新签名，未知和孤块交易继续保留核验。
- [F-018] 新案启动期允许预先公开的创始成员作为候选后备，但每人仍须质押并接受利益冲突排除，平台不得逐案手选。少于 8 名社区成员时保留全部创始成员，8～11 名时最多保留 5 名，达到 12 名后新案只使用社区成员；阶段和创始名单在开案时固化，既有案件不因人数或部署配置变化改组。

- 一致性: 争议冻结状态必须与 [[6.escrow-sync-and-wallet]] 的资金操作互斥，不允许争议进行中同时有未经仲裁授权的结算/退款发生。
- 可审计: 仲裁决定的证据、理由、操作者、执行结果需要长期保留，不因后续数据清理而丢失。

## 验收标准

- [x] [AC-001] 争议创建后，该任务对应的资金无法通过正常验收/超时流程被结算或退款。
- [x] [AC-002] 双方均可查询到当前争议状态、证据提交截止时间。
- [x] [AC-003] 仲裁员做出决定后，在链上交易确认前，界面展示「处理中」而非「已完成」。
- [x] [AC-004] 每个仲裁决定的理由、提交的证据、操作仲裁员、最终资金执行结果均可在审计记录中查询到。
- [x] [AC-005] 非仲裁员角色无法调用仲裁决定接口。
- [x] [AC-006] 未达到 YD 门槛、已申请退出或交易证据不属于当前钱包时，不能获得 DAO 仲裁资格。
- [x] [AC-007] 发布者、Agent 运营钱包和收款钱包不会被分配到关联案件；成员不足时案件保持可恢复等待状态。
- [x] [AC-008] 两票多数最多生成一份裁决和一份资金 outbox；重复投票、并发最后一票及非法比例不会产生重复结算。
- [x] [AC-009] DAO 与平台仲裁使用同一套多 Agent 分账规则；链上确认前资金持续冻结，确认后任务、争议、裁决和托管状态在同一事务收敛。
- [x] [AC-010] 新版案件由独立合约约束首审、申诉窗口和终审，平台不能在申诉期提前释放托管资金。
- [x] [AC-011] Sepolia 案件从冻结候选中接受真实 VRF 回调，首审与终审不重抽且终审排除首审成员。
- [x] [AC-012] 终审参与不足及全案超时不会永久冻结资金；恢复角色窗口与到期公开兜底均有合约验证，真实恢复退款已确认。
- [x] [AC-013] 钱包付费申诉、五人终审、中位数部分结算、仲裁奖励和保证金领取已在同一 Sepolia 案件闭环。
- [ ] [AC-014] 真实文件附件完成浏览器上传、授权下载、摘要复核和当事人钱包锚定，并完成正式环境异地备份恢复演练。
- [x] [AC-015] 新增奖励在用户在线时展示一次到账提示，分页记录和跨页未读状态完成浏览器视觉验收。

## 开放问题

- V1 旧部署保留平台授权仲裁与链下分案；v4 新案不开放平台直接资金裁决。Sepolia 新案已经采用 1 USDC 保证金、0.1 USDC 服务费与 `ReturnAlways`，正式生产运营窗口仍待确定。
- 当前体验库已迁移到 0050、`dirty=false`；Sepolia 合约、VRF subscription/consumer、奖励池和 8 名创始仲裁员已经启用。真实 VRF、钱包付费申诉、终审中位数结算、期限恢复、保证金领取、在线新增奖励通知与分页记录视觉验收均已完成；真实文件附件的上传/下载与钱包锚定及第三方审计仍未完成。
- YD 奖励默认自动转入用户钱包，平台承担发奖 Gas；只有付款事件经链上确认才显示到账并通知用户。转账失败不影响任务结算/仲裁，保留原交易、退避重试及去重。历史合格事实必须能够补扫，不要求用户重新执行行为。
- 启动期最低质押和创世活动单钱包上限均为 100 YD；旧质押不减少，退出仍按既有冷静期全额领取。正式生产活动窗口尚未确定。
- 本机 Sepolia 验收已使用项目专用加密 keystore signer；正式托管环境的密钥管理与监控、恢复角色多签、真实分叉奖励补偿、异地证据备份与罚没仍待补充。新版有期限恢复逻辑已部署并完成真实恢复闭环；历史 `stalled` 案件不能迁移，已落库的补偿意向仅作为审计事实保留，当前不再提供新建或付款入口。案件失败命令、规范最终裁决及奖励游标的等价历史恢复已有受控内部入口，详见 [实施与限制](../../docs/dao-chain-arbitration.md)。
