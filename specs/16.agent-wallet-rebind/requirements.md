# Agent 钱包换绑 — 需求规格

## 概述

Agent 提供者更换收款钱包地址的安全流程：新钱包签名证明所有权 + 独立站外确认 + 冷静期，冷静期内原地址仍是唯一生效的结算目的地，给账号真正的主人一个拦截异常换绑的窗口。站外确认渠道尚待本 feature 实施前确定，不能再依赖所有 Agent 上架时强制填写邮箱。参考行业惯例（交易所提现地址变更流程）设计，详见 [[2.agent-registration]] 的开放问题。

本 feature 是 `/yd:prd --change` 追加的 feature：[[2.agent-registration]] 原本将换绑列为"MVP 不支持"的开放问题，经用户确认需要支持后拆出独立 feature（换绑流程涉及签名验证、站外通知、冷静期定时任务等，是一个独立的高内聚闭环，塞进已满 8 任务上限的 feature 2 会超出单 feature 任务数限制）。

## 用户故事

- 作为 Agent 提供者，我的钱包丢了私钥或需要迁移，我想要安全地把收款地址换成新钱包，而不是永远被锁定在旧地址上。
- 作为平台，我想要即使账号本身被盗，攻击者也无法立刻把收款地址改成自己的并卷走后续收入，以便保护提供者的资金安全。
- 作为 Agent 提供者，如果我没有发起过换绑但收到了换绑通知，我想要能立刻一键拦截，以便阻止账号被盗造成的损失。

## 功能需求

1. [F-001] 发起换绑：提供者提交新钱包地址，发起换绑请求。
2. [F-002] 新钱包所有权验证：要求用新钱包对平台生成的一次性挑战消息（含随机数，防重放）做标准以太坊消息签名，验证发起人确实控制这个新地址。
3. [F-003] 站外确认：验证通过后，通过本 feature 独立配置并验证过的站外渠道发送通知，附带“这不是我操作的，立即取消”的一次性链接；不把站内消息作为唯一防线（账号若已被盗，攻击者也能看到站内消息）。具体渠道和所有权验证方式在实施前完成高影响设计评审。
4. [F-004] 冷静期：默认 24 小时（可配置），冷静期内旧地址仍是唯一生效的结算目的地，`agents.wallet_address` 字段本身不变。
5. [F-005] 取消换绑：冷静期内点击取消链接，换绑请求立即作废，不需要额外身份验证（链接本身即一次性凭证）。
6. [F-006] 到期生效：冷静期结束且未被取消，系统自动将 `agents.wallet_address` 切换为新地址，写入审计记录。
7. [F-007] 结算隔离：冷静期内如有任务进入结算，结算目的地读取"当前生效地址"（旧地址），不受待生效换绑请求影响。

## 非功能需求

- 安全: 挑战消息签名验证复用标准 Ethereum 消息签名验证（recover 出的地址必须与提交的新地址一致），不接受未经签名验证的地址变更请求。
- 可靠性: 冷静期定时任务需要幂等（重复执行不会重复切换或重复通知）。
- 可审计: 发起、签名验证、通知、取消、生效每个环节都要留痕。

## 验收标准

- [ ] [AC-001] 未完成新钱包签名验证的换绑请求不会进入冷静期。
- [ ] [AC-002] 冷静期内，无论换绑请求是否存在，任务结算都只会打给当前生效地址（旧地址），不会打给「待生效」的新地址。
- [ ] [AC-003] 点击取消链接后，换绑请求状态立即变为已取消，冷静期到期定时任务不再处理该请求。
- [ ] [AC-004] 冷静期到期且未取消时，`agents.wallet_address` 自动切换为新地址，且该变更在 `audit_logs` 中可查询到完整链路（发起、签名验证、通知发送、生效）。
- [ ] [AC-005] 同一 Agent 同时只能有一个进行中的换绑请求，重复发起需先取消或等待当前请求完成。
