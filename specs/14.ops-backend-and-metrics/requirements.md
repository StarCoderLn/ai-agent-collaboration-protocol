# 运营后台与核心指标 — 需求规格

## 概述

提供运营后台的角色权限体系、任务查询、派发失败查询、超时处理、交易状态核对，以及 MVP 核心成功指标的埋点与看板。对应 PRD §5.6 与 §11 P4 的 OPS-R、DATA-R。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 用户故事

- 作为运营人员，我想要查询任务、派发失败原因和交易核对异常，以便及时处理线上问题。
- 作为平台，我想要高风险操作（如仲裁决定、强制状态变更）需要二次确认，且所有操作可审计，以便降低误操作和滥用风险。
- 作为产品，我想要 MVP 核心成功指标（任务成功交付率、首次验收通过率、任务争议率、Agent 接单成功率、平均匹配耗时、平均交付周期）有可用埋点和看板，以便评估 MVP 表现。

## 功能需求

1. [F-001] 角色权限体系：钱包会话负责识别任务发布者和 Agent 提供者；后台角色复用现有 `platform_actor_roles`，在其上集中映射仲裁员、运营和平台管理员的权限点。历史 `agent_reviewer` 只为审计兼容保留，不恢复人工准入权限。后台查询和操作必须由服务端权限守卫控制，不得信任客户端角色声明。
2. [F-002] 任务查询：运营可查询全量任务及其状态，支持按状态、时间、异常类型筛选。
3. [F-003] 派发失败查询：可查询派发失败原因和重试次数（复用 [[9.dispatch-and-acceptance]] 的 `dispatch_attempts`）。
4. [F-004] 超时处理：可查询并处理超时任务（复用 [[11.execution-tracking-and-delivery]] 的超时状态）。
5. [F-005] 交易核对：展示链下记录与链上状态的不一致告警（复用 [[6.escrow-sync-and-wallet]] 的 `reconciliation_alerts`）。
6. [F-006] 高风险操作二次确认：仲裁决定、强制状态变更等高风险操作需要二次确认交互。
7. [F-007] 操作审计查询：可查询操作者、时间、对象、操作前后状态和原因（复用共享 `audit_logs` 表）。
8. [F-008] 核心指标埋点：任务成功交付率、首次验收通过率、任务争议率、Agent 接单成功率、平均匹配耗时、平均交付周期。
9. [F-009] 指标看板：展示上述核心指标，支持按时间范围查看趋势。

## 非功能需求

- 权限: 所有后台查询和操作接口必须经过角色权限中间件校验，未授权角色的请求一律拒绝。
- 性能: 指标看板查询基于每日预聚合数据，不在请求时对全量历史数据实时聚合。

## 验收标准

- [ ] [AC-001] 非运营/仲裁员/管理员角色调用后台查询或操作接口被拒绝。
- [ ] [AC-002] 高风险操作（仲裁决定等）在未完成二次确认前不会执行。
- [ ] [AC-003] 运营可查询到指定任务的派发失败原因、重试次数和交易核对异常。
- [ ] [AC-004] 操作日志可按操作者、对象、时间范围查询，且记录操作前后状态。
- [ ] [AC-005] 指标看板展示的六项 MVP 成功指标数值与其定义（PRD §1.4）计算口径一致。

## 开放问题

- 权限分级与审批方式待确认（PRD §3 角色表标注「权限分级与审批方式待确认」），本设计以简化 RBAC（角色→权限点的静态映射）实现，不支持动态审批流，如需更复杂的权限模型需重新评估。
- MVP 成功指标的具体目标值均待确认（PRD §1.4 全部标注「待确认」），本 feature 只负责指标可计算、可展示，不对目标值本身做任何假设或告警阈值判断。
- `[2026-08-20 补记]` **服务等级、告警阈值、备份恢复、容量目标（PRD §14 P1-3）**：这是运维/SLA 定义工作，不影响本 feature 的接口和数据结构（监控覆盖范围、告警关联可执行处理说明这些结构性要求已经在设计里），但具体的"响应时间目标是多少""数据备份频率多久"这类数值需要产品/运维在试运行前明确，不阻塞当前开发。
