# Agent 接入协议基础设施 — 需求规格

## 概述

定义平台与第三方 Agent 之间的认证签名、幂等键、错误码和超时重试语义，作为后续 Agent 注册（2）、健康检查（3）、派发（9）、执行结果提交（10）等 feature 的共享基础契约。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构（Go 分发引擎 + Next.js/AWS Lambda 交易服务 + PostgreSQL + AWS SQS/SNS + Ethereum 合约）

## 用户故事

- 作为 Agent 提供者，我想要一份清晰、版本化的接入协议，以便我的 Agent 能被平台安全调用，而不需要理解平台内部实现。
- 作为平台工程师，我想要统一的认证、幂等和错误码机制，以便派发、健康检查、结果提交都遵循同一套契约，不在各处重复实现。

## 功能需求

1. [F-001] 双向请求签名与认证：平台调用 Agent（派发、取消通知）与 Agent 回调平台（进度上报、结果提交、健康检查响应）均使用签名验证身份。
2. [F-002] 统一幂等键规范：派发请求、结果提交、Webhook 回调必须携带幂等键；平台侧持久化去重，重复请求返回幂等结果而非重复处理。
3. [F-003] 统一错误码与超时/重试语义：区分认证失败、协议不兼容、连接超时、Agent 内部错误四类，各类别有独立的重试与退避策略。
4. [F-004] 凭证轮换与防重放：签名包含时间戳与 nonce（或等效机制），超出时间窗口或 nonce 已使用的请求被拒绝；支持凭证轮换期间新旧凭证并行有效。
5. [F-005] 协议版本化：每个请求携带协议版本号；平台需能识别不兼容版本并返回明确错误，而不是静默失败。
6. [F-006] `[v2 新增]` 沙箱模式标记：请求携带 `call_type`（`sandbox` / `production`）标记位，签名覆盖该字段防篡改；平台侧的审计记录、Agent 历史统计、评分计算等必须能据此识别并排除沙箱调用，不让测试调用污染 Agent 的正式历史数据。
7. [F-007] `[v3 新增]` 过期记录清理：`idempotency_records`（TTL 7 天）与 `used_nonces`（TTL 覆盖签名时间窗口外的合理缓冲，默认 24 小时）超期后由定时任务批量删除，防止两张表无限增长影响查询性能；清理周期和保留时长均为可配置项。
8. [F-008] `[v5 新增]` TypeScript Agent SDK：第三方提供者只实现任务执行函数，SDK 统一承担 AICP v1 验签、Nonce、防重放、并发幂等、HTTP 传输、健康检查、异步接单和签名回调；Mastra 与 LangGraph 通过可选适配器接入，不得成为核心协议的强制依赖。
9. [F-009] `[v6 新增]` 默认快速 HTTP JSON：普通提供者只需提供同域 `/healthz` 与同步任务执行端点；`访问密钥`为可选 Bearer Token。平台负责派发幂等、接单确认、状态推进、同步结果持久化与内部转交恢复，第三方无需安装 SDK、实现 HMAC 或回调。未显式声明接入模式的历史客户端继续按 `aicp_hmac` 处理，不得静默降级认证。

## 非功能需求

- 性能: 签名验证与幂等查重的单次开销不得成为派发链路的瓶颈（P95 < 50ms）。
- 安全: 签名密钥、Webhook 密钥不得以明文形式出现在日志或错误信息中；防重放窗口需可配置。
- 兼容性: 协议本身不绑定具体 Agent 开发框架（Mastra/LangChain/LangGraph 均可接入），也不绑定具体资金链（MVP 资金侧选定 Ethereum，但协议层与链无关）。
- 快速接入安全: 服务探测必须要求已认证会话，正式环境仅允许公网 HTTPS，并在 DNS 校验后固定已验证 IP，防止匿名 SSRF 与 DNS rebinding。

## 验收标准

- [x] [AC-001] 使用错误或过期签名调用受保护端点时被拒绝，并返回统一错误码（不是裸 500）。
- [x] [AC-002] 相同幂等键的重复请求不会产生重复的派发记录或重复的结果提交。
- [x] [AC-003] 认证失败、协议不兼容、连接超时、Agent 内部错误四类场景可通过响应中的错误码明确区分。
- [x] [AC-004] 重放同一个（时间戳+nonce）组合的历史请求被拒绝。
- [x] [AC-005] 协议规格文档可供第三方团队独立阅读并据此实现一个测试 Agent 的最小可用集成。
- [x] [AC-006] `[v2 新增]` 携带 `call_type=sandbox` 的请求可在审计记录和统计查询中被明确标记和排除，不会计入 Agent 的正式任务历史或评分样本。
- [x] [AC-007] `[v3 新增]` 超过 TTL 的 `idempotency_records`、`used_nonces` 记录会被清理任务删除；未过期的记录不受影响；清理任务本身幂等（重复执行不报错、不误删未过期记录）。
- [x] [AC-008] `[v5 新增，2026-09-12 更新]` `@aicp/agent-sdk` 与 Go 共享签名测试向量；现有论文 Agent 和 10 个产品工作流 Agent 实际复用 SDK 的协议、幂等及 Node HTTP 边界，接入示例不再复制协议实现。
- [x] [AC-009] `[v6 新增]` 快速 Agent 可在无密钥或 Bearer Token 两种情况下通过同域 `/healthz` 测试，并以一次同步响应返回 1～3 个受支持产物；内部转交暂时失败时只重试已保存结果，不重复调用 Agent。快速 Agent 不生成生命周期 Webhook，历史 HMAC Agent 继续生成。

## 依赖

- 无外部服务依赖；本 feature 是后续所有 Agent 交互类 feature（2、3、9、10、15）的前置基础。
