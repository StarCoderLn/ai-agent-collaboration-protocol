# 五维评分系统 — 需求规格

## 概述

计算并展示 Agent 的五维评分（完成强度、质量反馈、沟通体验、争议率、历史完成规模），发布者评分与系统计算分离，评分规则版本化且可追溯。对应 PRD FR-R01。

> 2026-08-30 正式工作流映射：节点候选读取本 feature 的正式 Agent 得分快照；节点选择、
> 执行、验收、返工和里程碑结算均持久化。只有已确认的正式任务事实进入评分证据，
> 本地沙箱调用和未分配候选不得写入正式评分快照。

## 用户故事

- 作为发布者，我想要对已完成任务的质量和沟通体验评分，以便帮助其他发布者做出选择。
- 作为平台，我想要争议率和历史完成规模由系统客观计算而非人工输入，以便评分不被提供者操纵。
- 作为新 Agent 提供者，我想要评分系统对小样本做合理的统计校正，以便不因偶然的一次五星评价被过度信任，也不因偶然的一次低分被过度惩罚。

## 功能需求

1. [F-001] 五维评分维度：完成强度、质量反馈、沟通体验、争议率、历史完成规模。
2. [F-002] 评分来源分离：质量反馈和沟通体验由发布者评分；争议率与历史完成规模由系统计算，提供者不可修改系统计算项。
3. [F-003] 样本量展示：评分展示需附带样本量。
4. [F-004] 规则版本化：评分规则有版本号，历史评分可从任务记录追溯计算依据。
5. [F-005] 小样本校正：质量评分采用贝叶斯平滑或等价方法，新 Agent 不因单条高分评价直接排到成熟 Agent 前面。
6. [F-006] 时间维度：展示近期指标与全周期指标，旧评价按明确规则衰减，但原始记录不删除。
7. [F-007] 争议率口径：只计算经仲裁确认责任的争议事件；撤销或判定 Agent 无责的争议不扣分。
8. [F-008] 历史收入处理：使用对数缩放，仅作为置信度信号，不作为质量的主要替代指标，不按全站最大收入归一化。
9. [F-009] 响应速度与沟通体验分开：系统计算响应时间，发布者只评价沟通质量本身。

## 非功能需求

- 可追溯性: 任意历史评分快照必须能定位到当时生效的规则版本号与输入数据。
- 一致性: 评分计算结果在同一规则版本和相同输入下必须可复现（复用 [[8.matching-and-candidates]] 已验证的「规则版本化+纯函数计算」模式）。

## 验收标准

- [x] [AC-001] 争议率与历史完成规模字段无法通过提供者可访问的任何接口修改。
- [x] [AC-002] 评分展示附带样本量，样本量过小时的展示方式与样本充分时有区分（如附加提示，而非隐藏该维度）。
- [x] [AC-003] 只有 1 条五星评价的新 Agent 综合质量分不会超过有大量评价且平均分较高的成熟 Agent。
- [x] [AC-004] 已撤销或判定 Agent 无责的争议不计入争议率分子。
- [x] [AC-005] 任一 Agent 的评分可追溯到具体的规则版本号和参与计算的历史事件。
