# 任务创建与发布预览 — 需求规格

## 概述

发布者填写任务信息、平台校验必填项与格式、按受控分类树选择分类并选择或输入技能标签，发布前预览摘要与费用。对应 PRD FR-T01。任务主状态机在本 feature 首次定义，作为后续所有任务相关 feature 的权威依据。

> 2026-08-30 正式工作流映射：发布页写入本 feature 定义的正式任务；USDC 托管确认后
> 由任务服务在同一事务中创建持久化工作流。旧页面级体验状态已经删除，本文定义的
> 任务主状态机仍是任务生命周期唯一权威，节点状态只描述工作流内部执行。

## 用户故事

- 作为发布者，我只想填写真实需求和匹配所需的分类、标签、预算、截止时间，由平台整理其余字段，而不是面对长表单或理解内部“结构化任务合同”。
- 作为发布者，我想要在提交前看到完整预览（费用、验收方式、不可逆提示），以便在托管资金前确认无误。
- 作为平台，我想要分类受控、平台推荐标签可运营，同时允许规范化的用户标签精确匹配，以兼顾稳定推荐与长尾需求。

## 功能需求

1. [F-001] `[v9 修改]` 任务领域模型仍包含标题、分类、描述、验收标准、交付物及格式、计价方式、预算、币种、截止时间、所需能力、标签、附件、可见性和分配模式；快速发布页要求用户填写任务标题、详细需求、服务分类、技能标签、固定预算和截止日期。服务分类与技能标签和 Agent 上架共用同一组件及受控分类树；分类下拉隐藏仅用于组织的父级节点和层级路径，只展示简明的可执行末级服务。技能标签可以选择平台推荐词条，也可以输入自定义值，两者分别写入现有 `categoryId`、`tags` 字段。验收与交付说明使用不增加新事实的通用规则，所需能力由用户选择的分类和标签形成。页面整理结果必须完整提交给现有 API，不得放宽匹配、服务端、金额或状态机校验。（可见性与分配模式的详细校验规则在 [[7.task-visibility-and-mode]] 中定义。）
2. [F-002] `[v5 修改]` 截止时间校验：必须晚于当前时间，并满足平台最短执行周期（默认 30 分钟，可配置）。这条下限**只保证平台自身调度流水线（匹配 + Agent 接单等待）有足够时间跑完**，不代表任务本身能在这个时间内被真正完成——"这类任务/这个 Agent 实际需要多久"由 [[8.matching-and-candidates]] 已有的"预计时长 vs 截止时间"硬约束逐个 Agent 判断，不按任务分类重复设置一套时长规则（避免同一件事被两套机制分别管，口径还可能互相矛盾）。
3. [F-003] `[v7 修改]` 分类与标签：分类从受控分类树选择；标签支持平台建议、用户自定义、同义词归一和去重。所有标签统一小写并压缩连续空格，最多 10 个、单个最多 32 个字符；禁用词、逗号和控制字符不得通过自定义输入绕过。自定义标签按任务与 Agent 规范化后的精确文字交集参与匹配，平台不做不可解释的模糊合并。
4. [F-004] 计价方式校验：固定价只填单一金额；预算区间要求最低金额不大于最高金额；币种只选择一次，不允许区间两端使用不同币种。
5. [F-005] `[v10 修改]` 发布及托管前预览：任务预算必须在 1–100,000 USDC 之间。展示任务摘要、托管预算、预计平台服务费、Agent 预计最高实收和不可逆操作提示。预计费用计算仍为 `平台服务费 = max(成交金额 × 0.4%, 平台结算 gas 成本估算)`；MVP 当前最低平台服务费为 0.05 USDC。**平台服务费由 Agent 提供者的结算收入承担**：发布者托管的预算已经包含平台服务费，不在预算之外加价；Agent 实际到账 = 成交金额 − 平台服务费，未成交的预算差额退还发布者。页面必须明确展示费用承担方，但不单独展示恒为 0 的费用字段，避免用没有信息增量的字段增加用户疑虑。费率、最低服务费与规则版本均由服务端权威配置返回，前端不得复制算法。
6. [F-006] 草稿保存：未完成的任务可保存为「草稿」状态，提交后进入「待托管」，触发任务主状态机的首个合法迁移。
7. [F-007] `[v2 新增]` 附件大小/类型上限按任务分类分别配置，不使用统一上限（不同分类的典型交付物大小差异很大，如文档类几百 KB、图片类几十 MB、视频类可能到 GB 级）；分类-上限映射存于可配置表，产品可随时调整具体数值，不需要改代码或重新部署。MVP 默认值：文档类 50MB、图片类 20MB、视频类 1GB（配合分片上传）；未匹配到专属配置的分类使用平台默认值 20MB。

## 非功能需求

- 性能: 创建任务表单的分类/标签联动查询 P95 < 300ms。
- 安全: `[v2 修改]` 附件上传按分类校验类型白名单与大小上限（F-007），并做基础安全扫描占位（真实病毒扫描集成非本 feature 范围，见开放问题）。
- 兼容性: 任务状态机需要与 [[6.escrow-sync-and-wallet]]、[[8.matching-and-candidates]] 等后续 feature 共享同一权威定义，不允许各自维护副本。

## 验收标准

- [x] [AC-001] 截止时间早于当前时间或短于最短执行周期时不可提交，并提示具体原因。
- [x] [AC-002] `[v7 修改]` 合法自定义标签能够与平台推荐标签一起提交并参与精确匹配；同义词、大小写、连续空格和重复项被归一，命中禁用词或超过数量/长度边界时提交被拒绝并给出字段提示。
- [x] [AC-003] 预算区间最低金额大于最高金额时不可提交。
- [x] [AC-004] 发布前预览页准确展示预计费用与不可逆提示，且与实际提交的数据一致（不是静态文案）。
- [x] [AC-007] `[v8 修改]` 合法小额任务（不低于 1 USDC）在比例费用低于 0.05 USDC 时按最低服务费计算；托管前展示的费率、最低服务费和预计金额均来自服务端，且与 [[11.execution-tracking-and-delivery]] 的实际验收结算调用同一份 `CalculatePlatformFee()`，不允许前端重算。
- [x] [AC-005] 提交成功后任务状态为「待托管」，且该迁移在任务状态机中是唯一合法的起始迁移路径。
- [x] [AC-006] `[v2 新增]` 超过对应分类大小上限或类型不在白名单内的附件上传被拒绝，且提示信息指明该分类的具体上限；调整分类上限配置后新上传立即按新值校验，不需要发版。
- [x] [AC-008] `[v9 修改]` 发布页不展示结构化任务合同；用户填写 6～72 个字符的任务标题、详细需求、服务分类、至少一个技能标签、预算和截止日期即可提交完整 API 请求。分类/标签的叫法、平台推荐、自定义输入和移除交互与 Agent 上架一致，分类只显示不带层级路径的可执行末级服务；需求少于 30 个 Unicode 字符时提示补充真实信息，没有合适推荐标签时仍可添加合法自定义标签发布。提交失败时页面滚动并聚焦到首个错误字段，不允许只在表单底部给出用户难以定位的汇总提示。

## 开放问题

以下按"能否由工程判断先落地默认值"分成两类，避免把需要产品/法务/财务决策的事项和工程可以自行拍板的事项混在一起：

### 工程判断已落地默认值（`[v2]`，可随时按需调整，不阻塞开发）

- ~~附件类型/大小~~ `[v2 已确认]`：按分类分别配置（F-007），MVP 默认值见 F-007，产品觉得不合适可直接改配置表，不需要 `--change` 走一遍需求变更流程。
- ~~平台最短执行周期~~ `[v5 已确认]`：默认 30 分钟（覆盖匹配 5 秒 + 接单等待 5 分钟的流水线开销，留 3-6 倍安全余量），可配置项，产品有异议可直接调整数值。
- ~~平台服务费费率、金额门槛和承担方~~ `[v8 已确认]`：名义费率 0.4%，最低服务费 0.05 USDC，任务预算最低 1 USDC；平台服务费由 **Agent 提供者结算收入中扣除**，发布者看到的预算即最高托管额，不在预算之外额外收费。费率与最低服务费均为服务端可配置项。

### 需要产品/法务/财务决策，非工程判断（不应由工程给"合理默认值"）
- **附件保留期限**：数据保留法规因司法辖区而异（如 GDPR 类要求），需法务判断适用规则；当前未设默认值，实现时预留可配置的保留期字段，数值待法务确认后填入。
- **恶意文件扫描策略**：具体使用哪个扫描服务/引擎待安全团队确认，MVP 先实现类型/大小硬校验作为过渡，真实病毒扫描集成留作后续任务，不阻塞本 feature 当前范围。
