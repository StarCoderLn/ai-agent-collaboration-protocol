# 任务创建与发布预览 — 需求规格

## 概述

发布者填写任务标题、服务分类和截止日期，补充说明可选；平台校验后自动识别能力并创建正式工作流。对应 PRD FR-T01。任务主状态机在本 feature 首次定义，作为后续所有任务相关 feature 的权威依据。

> 2026-08-31 正式工作流映射：发布页写入本 feature 定义的正式任务；提交时由任务服务
> 在同一事务中创建持久化工作流，任务进入 `planning`。所有节点选定 Agent 并冻结准确
> 报价后才进入 `awaiting_escrow`。本文定义的任务主状态机仍是任务生命周期唯一权威，
> 节点状态只描述工作流内部选择和执行。

## 项目信息

- 项目名: ai-agent-collaboration-protocol
- 架构类型: 多服务架构

## 用户故事

- `[2026-09-06]` 普通任务不默认购买 PRD；标题与可选说明直接作为执行范围。明确缺少主题/用途时就近提示补充，未指定呈现细节由 Agent 合理补足，不设置自由发挥开关或追加授权文案。新软件任务为设计→开发，图片/视频为单节点；用户主动发布的 PRD 服务仍可正常匹配，页面不新增购买开关。旧工作流和冻结资金不迁移。
- 作为发布者，我只想用任务标题、服务分类和截止日期快速开始；如有必要再补充场景或限制，不必在尚未拆分任务时猜预算或学习平台标签协议。
- 作为发布者，我想先看到工作流与候选价格区间，再决定是否填写预算上限，最终只按选中 Agent 的冻结报价总和托管。
- 作为平台，我想从用户自然语言识别规范能力，并允许发布者在匹配阶段修正，兼顾低操作负担、可解释性与长尾需求。

## 功能需求

1. [F-001] `[v13 修改]` 任务领域模型仍保留标题、分类、描述、验收标准、交付物、计价、币种、截止时间、能力、标签和可见性等字段；快速发布页只要求任务标题、服务分类和截止日期，补充说明可选。补充说明为空时复用标题作为最小原始描述，不能虚构功能事实。发布表单不显示技能标签和预算；计价字段保持为空直到所有工作流节点选定 Agent 后由服务端写入准确固定价。可见性与分配模式规则见 [[7.task-visibility-and-mode]]。
2. [F-002] `[v5 修改]` 截止时间校验：必须晚于当前时间，并满足平台最短执行周期（默认 30 分钟，可配置）。这条下限**只保证平台自身调度流水线（匹配 + Agent 接单等待）有足够时间跑完**，不代表任务本身能在这个时间内被真正完成——"这类任务/这个 Agent 实际需要多久"由 [[8.matching-and-candidates]] 已有的"预计时长 vs 截止时间"硬约束逐个 Agent 判断，不按任务分类重复设置一套时长规则（避免同一件事被两套机制分别管，口径还可能互相矛盾）。
3. [F-003] `[v13 修改]` 分类与能力：分类从受控分类树选择。提交时服务端从标题、说明和能力描述中按版本化同义词词表识别规范标签，最多 10 个；未识别到标签仍可按分类和任务描述生成候选。匹配阶段向用户展示节点能力，允许从平台建议点选、自由补充或删除；所有修改仍须通过服务端同义词归一、禁用词和字符边界校验。
4. [F-004] `[v14 修改]` 计价延后：草稿和 `planning` 任务允许计价为空；最后一个工作流节点选定 Agent 时，服务端汇总当前报价并写入固定价。`awaiting_escrow` 无 intent，或 intent 已明确失败且没有 Deposit 哈希/链事件时，更换节点 Agent 必须按新报价原子修订固定价及失败 intent 金额；金额仍只允许 USDC 6 位最小单位整数。
5. [F-005] `[v13 修改]` 匹配阶段预算上限可选，范围为 1–100,000 USDC，只写入 workflow run/node 的 preference 字段并影响候选排序，不得写入 `budget_cap_minor`、`agreed_amount_minor`、`quoted_total_minor` 或托管 intent。全部节点选择完成后，托管页使用冻结报价准确总和，并按同一权威手续费规则展示平台服务费和 Agent 实收明细。
6. [F-006] `[v12 修改]` 草稿保存：未完成的任务可保存为 `draft`；提交时在同一事务中创建正式 workflow run、节点和依赖边，任务进入 `planning`。所有节点的 Agent 与报价都冻结后，任务才进入 `awaiting_escrow`；发布动作本身不得生成托管 intent、占用 Agent 或派发任务。
7. [F-007] `[v2 新增]` 附件大小/类型上限按任务分类分别配置，不使用统一上限（不同分类的典型交付物大小差异很大，如文档类几百 KB、图片类几十 MB、视频类可能到 GB 级）；分类-上限映射存于可配置表，产品可随时调整具体数值，不需要改代码或重新部署。MVP 默认值：文档类 50MB、图片类 20MB、视频类 1GB（配合分片上传）；未匹配到专属配置的分类使用平台默认值 20MB。
8. [F-008] `[v14 新增]` 发布者可以删除 `draft` 或 `planning` 任务。删除采用软归档，任务立即从市场、工作台、详情和统计中隐藏，但任务行、工作流、事件和审计记录保留。`awaiting_escrow` 及其后状态不得通过删除绕过资金与履约状态机，必须走取消、退款或争议。

## 非功能需求

- 性能: 创建任务表单的受控分类查询 P95 < 300ms；发布动作不依赖标签建议请求。
- 安全: `[v2 修改]` 附件上传按分类校验类型白名单与大小上限（F-007），并做基础安全扫描占位（真实病毒扫描集成非本 feature 范围，见开放问题）。
- 兼容性: 任务状态机需要与 [[6.escrow-sync-and-wallet]]、[[8.matching-and-candidates]] 等后续 feature 共享同一权威定义，不允许各自维护副本。

## 验收标准

- [x] [AC-001] 截止时间早于当前时间或短于最短执行周期时不可提交，并提示具体原因。
- [x] [AC-002] `[v13 修改]` 发布表单不显示技能标签；服务端可从自然语言识别同义词并归一为规范能力。匹配阶段可增删能力，中文、日文等输入法组合文字时回车不得提前添加残缺内容。
- [x] [AC-003] `[v13 修改]` 发布时不校验或写入预算；匹配阶段非法预算偏好被拒绝，合法偏好不改变任何冻结金额字段。
- [x] [AC-004] `[v13 修改]` 节点全部选定后准确总价等于冻结报价之和，托管金额不得使用预算偏好或任何隐藏默认值。
- [x] [AC-009] `[v14 新增]` 待托管改选后准确总价与任务固定价仍等于全部节点冻结报价之和，任务保持 `awaiting_escrow`，且不会出现一半更新的中间状态。
- [x] [AC-007] `[v13 修改]` 合法成交报价不低于 1 USDC；节点选择完成后展示的费率、最低服务费和预计金额均来自服务端，且与 [[11.execution-tracking-and-delivery]] 的实际验收结算调用同一份 `CalculatePlatformFee()`，不允许前端重算。
- [x] [AC-005] `[v12 修改]` 提交成功后任务和 workflow run 均为 `planning`，节点为 `selecting`；只完成部分节点选择时仍为 `planning`，全部选完才原子迁移到 `awaiting_escrow`。
- [x] [AC-006] `[v2 新增]` 超过对应分类大小上限或类型不在白名单内的附件上传被拒绝，且提示信息指明该分类的具体上限；调整分类上限配置后新上传立即按新值校验，不需要发版。
- [x] [AC-008] `[v13 修改]` 发布页不展示结构化任务合同、技能标签或预算；用户填写 6～72 个字符的任务标题、服务分类和截止日期即可提交，补充说明允许为空并复用标题。提交失败时页面滚动并聚焦到首个错误字段，不允许只在表单底部给出汇总提示。
- [x] [AC-009] `[v14 新增]` 发布者确认删除规划前任务后，工作台和公开读取均不可再访问；数据库仍可查询到归档时间、工作流、`task.archived` 事件和 `task.archive` 审计。已进入资金流程的任务返回明确冲突错误且不改变任何记录。

## 开放问题

以下按"能否由工程判断先落地默认值"分成两类，避免把需要产品/法务/财务决策的事项和工程可以自行拍板的事项混在一起：

### 工程判断已落地默认值（`[v2]`，可随时按需调整，不阻塞开发）

- ~~附件类型/大小~~ `[v2 已确认]`：按分类分别配置（F-007），MVP 默认值见 F-007，产品觉得不合适可直接改配置表，不需要 `--change` 走一遍需求变更流程。
- ~~平台最短执行周期~~ `[v5 已确认]`：默认 30 分钟（覆盖匹配 5 秒 + 接单等待 5 分钟的流水线开销，留 3-6 倍安全余量），可配置项，产品有异议可直接调整数值。
- ~~平台服务费费率、金额门槛和承担方~~ `[v13 已确认]`：名义费率 0.4%，最低服务费 0.05 USDC，Agent 成交报价和可选预算偏好最低 1 USDC；平台服务费由 **Agent 提供者结算收入中扣除**，发布者托管的准确报价总和已包含服务费，不再额外收费。费率与最低服务费均为服务端可配置项。

### 需要产品/法务/财务决策，非工程判断（不应由工程给"合理默认值"）
- **附件保留期限**：数据保留法规因司法辖区而异（如 GDPR 类要求），需法务判断适用规则；当前未设默认值，实现时预留可配置的保留期字段，数值待法务确认后填入。
- **恶意文件扫描策略**：具体使用哪个扫描服务/引擎待安全团队确认，MVP 先实现类型/大小硬校验作为过渡，真实病毒扫描集成留作后续任务，不阻塞本 feature 当前范围。
